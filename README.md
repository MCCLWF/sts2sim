# sts2sim

《杀戮尖塔 2》（Slay the Spire 2）的非官方 C++ 无头模拟器，以及在它上面训练的整局 AI。

> **开发已暂停（2026-10-15）。** 这是最后一次完整快照：代码、设计文档、每一轮实验的计划和报告、工具、最终的策略包都在这里。开发历史没有公开。

- 游戏版本基线：v0.111.0（`41cef1ea`），Linux。
- 最终目标：静默猎手（Silent）A10 的整局 **NoSL** AI。NoSL 指实际游玩时只用当前看得到的信息做策略推理：不搜索、不模拟未来、不试动作回滚、不读档。
- 本项目与 Mega Crit 无关。

## 现在有什么

| 部分 | 状态 |
|---|---|
| 模拟器 | 按游戏代码逐文件移植到 C++。随机数、Decimal、排序与 .NET 逐位一致。五个角色的卡牌、遗物、药水、事件、商店、休息点和三幕整局都已接入 |
| 验证 | 进程内 oracle 直接运行正版 `sts2.dll`（不需要 Godot），逐决策对拍。最近两批新种子整局对拍：2000 局中 1996 局一致，1000 局中 997 局一致，规则分歧 0，其余 7 局是牌池容量上限。全部内容的条件覆盖还没有验收完；登记在册的偏离见 [`docs/audits/deviations.md`](docs/audits/deviations.md) |
| Env | Reset / Step / LegalActions / Clone / Hash / 快照。提供 C ABI、Python（ctypes）和 .NET SDK |
| NoSL AI | 能自己打完整局，但很弱：**进阶 10 至今 0 通关**，见下文 |
| 游戏内执行器 | `tools/NoslPilot`：Linux 原生 CPU 推理（不需要 Python）的 Mod，在正版游戏里接管静默猎手单人对局，有可拖动的推理面板，F8 暂停继续、F9 交还。[使用说明](tools/NoslPilot/README.md) |
| 策略包 | [`models/nosl-r12/`](models/README.md)：最后一个确认过的组合，可直接给执行器用 |
| CombatSolver 移植 | 简化实现，已停止移植，见下文 |

### AI 现在的水平

全部是在没见过的种子上、贪心执行、每局打到游戏自己的终局：

| | 进阶 10 | 进阶 5 | 进阶 0 |
|---|---|---|---|
| 进入第二幕 | 约 65% | 约 90% | 约 95% |
| 进入第三幕 | 约 3.6% | 约 21% | 约 30–38% |
| 通关 | **0**（累计数万局） | 约 0.3% | 约 0.5–0.7% |

起点（10 月 6 日的基础策略）在进阶 10 上进第二幕 28.7%、没有一局进第三幕。人类熟练玩家的进阶 10 胜率远高于此，离目标还有数量级的差距。

## 在做什么（停下时的状态）

AI 由两部分组成：**战斗**由一个策略网络打（PPO 训练）；**局外**（选路、选牌、升级、商店、事件）由基础策略加几层从数据里学出来的规则决定。所有规则都只读公开观察。下面是一路上真正经过留出种子确认的提高（每一轮都先登记问题、对照、预算和判据，再看结果；失败的轮次同样写了报告）：

| 轮 | 做了什么 | 留出确认的效果（进阶 10） |
|---|---|---|
| R1–R2 | 局外价值规则：从带随机探索的整局数据里学“这一步之后走多远” | 进第二幕 28.7% → 45.0% |
| R3 | 战斗在进阶 0/5/10 混合的课程上继续 PPO | 进第二幕 +3.5 个百分点 |
| R4 | 表规则：把探索时的随机动作当随机对照，按牌、按休息点统计平均效果 | 结果目标 +0.084 |
| R5 | 门口模型：拟合“带着这副牌能不能过前面的关口”，用它给选牌和升级打分 | +0.068（进第三幕 27 → 67 局 / 2048） |
| R10 | 一步前瞻标签（每个候选动作在 8 个重采样副本上打完这场）学出“哪个动作更好”，战斗里预测明显更好时才换 | +0.017（进第三幕 132 → 172 局 / 4096） |
| R12 | 守卫：不扔药水、药水栏满不买药水、不把金币和遗物留在奖励界面 | +0.007 |

结果目标 = 层数 / 50 + 0.5 × 幕数 + 2 × 通关，是“走得多远”的度量。R6–R9、R11 是没有带来提高的轮次（再训战斗、改回报、缩短信用视野、局外规则放到商店和休息点、多个模型取平均等），原因都写在各自的报告里。

停下时正在跑 R13，被中途停掉，只有部分调参集结果、没有留出确认：

- 前瞻标签从 97 万继续往 140 万加（只多了 1 段）。
- 低进阶另用一套守卫：进阶 0 上“血近满就升级”+0.019 [+0.012, +0.027]，“普通战斗血量三成以上不用药水”+0.018 [+0.001, +0.034]，“商店先删基础牌”进第三幕 +2.4 个百分点；同样的改法在进阶 10 上都更差（R10、R12 已量过）。代码里已支持按进阶切换守卫（`guards_low`），但这一套没有确认，没有进策略包。

逐轮的记录在 [`docs/roadmap.md`](docs/roadmap.md)（每轮一段）、[`docs/plans/`](docs/plans) 和 [`docs/reports/`](docs/reports)；最后的交接说明在 [`docs/notes/2026-10-09-nosl-handoff.md`](docs/notes/2026-10-09-nosl-handoff.md)。

## 遇到的困难

1. **战斗的强化学习不再动了。** 从第 650 次迭代起约 4000 万个决策，调参集上没有净变化。量过原因：两批互相独立的训练数据算出的策略梯度方向几乎不相关（余弦 0.0015），每一步更新基本是噪声。把回报按数据重新定价、缩短 GAE λ（梯度一致了十几到四十倍）都没有让整局变好，反而更差。
2. **模拟标签是真信号，但网络学得很慢。** 一步前瞻在同一开局的对照里很强（第二幕普通怪胜率 59% → 76–83%），标签方差里七成不是噪声；可是约 90 万个标签只让网络解释了留出标签方差的 12%，整局上的好处是 +0.017 到 +0.025。加标签有用，但涨得慢，靠加数量走不到通关。
3. **局外陷在“每一步都对、合起来不行”的状态里。** 战斗弱，每场都掉血，于是少升级、绕精英、不删牌、有药水就用——逐个决策看都是对的，合起来是一副约 29 张、4 张升级、基础牌几乎没删的牌组，过不了第二幕 Boss。“投资型”打法（多升级、删牌、打精英、留药水）在进阶 10 上试了都更差，在进阶 0 上却都更好：最优点随难度变，根子在战斗水平。
4. **没有能模仿的强老师。** 读真实状态（看得到抽牌顺序）的搜索在同一副牌、同一开局下，也只把每场战斗胜率从 89.8% 提到 93.8%，第二幕 Boss 只赢 31.6%；同一个搜索不给预知时比现有策略还差。10 月 4–6 日的三十多组小实验（教师蒸馏、奖励塑形、信用分配等）都没有稳定超过基础策略。
5. **看不见后半局。** 进阶 10 只有百分之三四的局进第三幕、0 通关，没有通关信号可学；“走多远”的指标对后期几乎没有分辨率，后期的改动在它上面看不出来。
6. **工程条件。** 只有一台笔记本（16 GB 内存），长任务经常被断电和重启打断；整局评价很便宜（4096 局几分钟），但生成标签、训练都要十几小时到几天。保真上还有登记在册的偏离（例如 O-010：滚石的伤害由特效节点驱动，无头宿主里回放不了）。

## 希望达成的目标

- **最终**：静默猎手 A10 整局高胜率（包括第三幕的两个 Boss），在 Linux 正版游戏里无人工输入打完，部署时只用公开观察和必要的公开历史做策略推理。
- **阶段**：进阶 0 稳定通关 → 进阶 10 稳定进第三幕 → 进阶 10 通关。
- **没来得及做、但有依据的方向**（给想接着做的人）：
  - 改战斗网络看到的东西和学的方式，而不是加量：例如直接学“前瞻选了哪个动作”的排序，给网络加上算过修正的伤害、能否斩杀、这回合挡不挡得住这类特征。
  - 专家迭代：用加了规则的新策略重新做前瞻和标签，让改进可以叠加。
  - 局外按难度区分打法，并且在整局打法这一层做随机对照（现在的探索只覆盖“当前打法 + 一步偏离”，精简、多升级的牌组在数据里几乎不存在，模型没法给它估价）。
  - 能看到牌组协同的门口模型（现在是按单张牌的线性模型）。

## Env 性能

2026-10-05，i7-14650HX，单线程，180 个战斗根的中位数：

| 操作 | 耗时 |
|---|---:|
| Clone（完整 Env） | 2.0 µs |
| Clone + 出一张牌 | 36 µs |
| Clone + 结束回合 | 122 µs |
| LegalActions | 13 µs |
| Hash | 12 µs |

- 连续推进（取合法动作、选择、执行）：14,670 决策/秒；加上 NoSL 观察编码后 9,753 决策/秒。
- 8 线程独立 Clone + 结束回合：约 4.4–6.1 万次/秒。
- 同机对比 [iRyougi/sts2-sim](https://github.com/iRyougi/sts2-sim) 的公开 Core（`2ac1c87`）：180 个根、540 个边界结果一致；Clone 约快 5.8 倍，连续推进约快 1.6–1.8 倍，单次出牌对方略快（33.5 µs）。两边克隆的范围和观察的内容不同，这些数字只作工程参考（[报告](docs/reports/2026-10-05-env-sts2ai-latest-performance.md)）。

## CombatSolver 移植

来源是 [Torch1230/CombatSolver](https://github.com/Torch1230/CombatSolver) 0.47.3。`search/combatsolver/` 是原生 C++ 跨回合 Beam 搜索，直接调用 Env；评分权重、路线比较、药水政策和转置支配规则照上游翻译（34,082 例政策差分通过），搜索的组织方式是简化实现。21 场起始牌组战斗上路线质量与上游相当（总战损 349 对 350）。10 月 3 日决定不再继续移植：上游更新很快，而最终目标本来就是不带搜索的 AI。它只用于离线诊断和当特权教师；第一版（专用预测后端）冻结在 `archive/combatsolver/`。

## 构建

需要 C++20 编译器（GCC 或 Clang）和 CMake ≥ 3.20。模拟器和单元测试不需要游戏文件。

```bash
git clone https://github.com/MCCLWF/sts2sim.git
cd sts2sim
cmake -B build -S . && cmake --build build -j
ctest --test-dir build --output-on-failure
build/sts2sim_cli smoke --seeds S1,S2,S3 --no-neow 1 --greedy 1   # 整局冒烟，每局一行 JSON
```

- oracle 对拍和内容导出需要正版游戏和 .NET 9 SDK，入口是 `scripts/check.sh`。游戏 DLL、反编译源码和本地化资源不在仓库里。
- 训练需要 Python、NumPy 和 PyTorch（`python/nosl/`）。报告里引用的 `artifacts/` 是本地的原始产物（权重、标签、日志，体积很大），没有公开；最终策略包在 `models/`。
- 构建模拟器不需要 `external/CombatSolver` 子模块。公开仓库里它固定在上游 0.47.3（`d7b4620`）；本地另有几处没有上游的补丁，依赖这些补丁的工具不能直接构建。
- 游戏内执行器的打包见 [`tools/NoslPilot/README.md`](tools/NoslPilot/README.md)。
