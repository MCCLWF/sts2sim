# Single-player Env / Random Foreseer functional inventory

Audit date: 2026-09-30. This records functional requirements and the 5266daf baseline, not current implementation acceptance. Current evidence is tracked in ../reports/2026-09-30-env-rf-api-checkpoint.md. Simulator checkout inspected: the API worktree at 5266daf. Vanilla truth: v0.111.0 source under ../Slay the Spire 2/src/Core. Random Foreseer reference: https://github.com/hotwords123/StS2.RandomForeseer, exact commit c4f14db684d831f9786d1c6af15b172b89d04939, tag v0.13.17, cloned outside the worktree at an external reference checkout.

The feature inventory below describes what the RF consumer asks to preview. RF's cloned-run RNG helpers, combat simulator, supported-model registries, and hand-maintained fast-forward logic are evidence of consumer demand only; they are not rule truth and should not be copied into Env. An Env prediction should execute the original operation on a private owned branch, using the real source model and pending context. If it reaches a choice or unsupported branch, it must return that state explicitly rather than infer one answer.

## Public surface at baseline 5266daf

The API currently has a legal-action one-step preview and owned successor (env/preview.cpp:32-58), four combat query families plus run queries (env/run_queries.cpp:205-303), and a v2 before/after projection around a legal action. Preview stops at choice, next decision, or ended state; it does not accept a caller-specified hypothetical hover operation or a general native stop boundary. Current result docs explicitly mark tracing incomplete and say arbitrary room/async capture, hover operations, full results, and causal records remain unfinished (docs/env-preview-api.md:48-66). The generic completion plan already calls for typed operations, source/context, explicit boundaries, choice continuation, and complete typed results (docs/plans/2026-09-27-generic-env-completion.md:32-60).

The most useful contract is one typed Predict entry point with a tagged operation, stable references into one owned state, and a stop policy. Its executor dispatches to ordinary legal actions where possible, and to a small set of narrowly typed native operation adapters for hover-only intent. All adapters call the same vanilla methods that an actual click/action invokes; clients never supply RNG objects or precomputed outcomes. Return an owned successor/continuation plus Exact, NeedsChoice, Unsupported, Truncated, or Invalid, a typed result, and optional causal trace. Query-only predictions such as Frozen Eye or next-act facts can stay queries. Hidden RNG state and hidden room contents are privileged facts, not agent observations.

## Proposed typed surface

A minimal typed contract preserves shared execution instead of proliferating RF-specific methods:

- PredictRequest { source_handle, operation, stop_policy, trace_options }, with a tagged operation and refs scoped to one source owned state. No caller-set RNG, arbitrary state mutation, or ignore-cost flag.
- Native operation tags for intent not expressible by LegalAction: RelicObtain {player_ref,relic_ref,source_ref,selection_order}, TransformCandidate {source_ref,card_refs,choice_ref}, EventOption {event_ref,option_ref}, RewardAlternative {reward_ref,alternative_id}, ShopPurchase {inventory_ref,entry_ref,player_ref}, RestSiteOption {room_ref,option_ref,player_ref}, CrystalSphereClick {minigame_ref,x,y,tool}. Next-act/Frozen-Eye are privileged queries, not mutation tags.
- Combat changes normally use legal UseCard, UsePotion, AnswerChoice, and EndPlayerTurn. Prediction of draw, generation, autoplay, random target and orb outcomes comes from tracing those native actions, not extra operations that reimplement card effects.
- Explicit stop policies: OperationSettled, NextChoice, NextPlayerDecision, EnemyTurnStarted, SafeCombatEnd, RoomSettled, and bounded step/time budget. A choice returns NeedsChoice plus a valid owned continuation; budget exhaustion returns Truncated. Result completeness and trace completeness are separate.
- Typed result contains generated model refs, targets/hits, changed piles/resources/reward/shop rows, option ids, and next_context_ref. Trace events carry order, actor, source model+instance, action/trigger, target and RNG stream/draw metadata only for privileged diagnostics. Every query/result includes an information-visibility label.
- Capture/hash source context with the operation: model ref, player/owner, room/reward/merchant/minigame, caller operation, current selected refs, selector preferences, pending task boundary and stable root snapshot. Unknown context returns Unsupported instead of silently selecting defaults.

## Completion gaps and risk limits

1. Current preview is one legal action, not “hover any object and execute its eventual native effect.” Run queries report existing facts but do not create hypothetical reward/relic/shop/event operations on a branch.
2. Local game-state restore is not real-game capture. Arbitrary async task/selection/minigame state, actual room screens and every pending event operation need explicit capture/continuation contracts; do not serialize a managed task stack.
3. Next-act and Crystal Sphere reveal privileged facts. RF fair-mode settings are client policy, not permission to expose these as normal RL observations.
4. RF combat prediction uses a mirror simulator, not complete vanilla execution. Its end-turn simulator intentionally mirrors selected phases and omits BeforeFlush handling; random card/event/merchant helpers also contain hand-maintained fast-forward code/TODOs. RF enumerates consumer requirements, but vanilla v0.111.0 must determine results.
5. The complete single-player RF matrix exceeds named examples. Every source reachable from normal v0.111.0 content, including hooks and nested choices, must go through generic execution or receive a precise Unsupported result. A list of currently-supported RF models is not a coverage claim.
