# NoSL Q5-a：策略在 Linux 实机里打完一整局——影子同步执行器

- 日期：2026-10-04。分支：`feat/nosl-q4d-reward-fix`（与 Q4-d、Q4-e 在同一条线上提交，代码互不依赖；报告分开）。
- 上级需求：[Silent A10 整局 NoSL 计划](2026-10-03-silent-a10-nosl.md) R01（整局执行能力）、R02（时序与可靠性）、F11（异常与接管）、
  §11 的 Q5。
- 这是 Q5 的第一步，只回答“能不能在真实游戏里从头打到结束”。它**不**宣称成品满足 NoSL 的部署审计，原因见“信息边界”一节。

## 问题

现在的证据都在模拟器和无 Godot 的正版逻辑（oracle）里。策略从没有在带界面的真实游戏进程里走过一步。

**问题**：给定一个种子，策略能不能在隔离的 Linux 正版游戏实例里，不要任何人工输入，从新开局一路操作到游戏自己判定死亡或胜利，
并且每一步真实游戏的公开状态都和策略以为的一致？

**假设**：能。依据：模拟器与正版逻辑在约 1,600 条策略轨迹上逐决策一致；游戏自带的 `AutoSlay`（厂商的冒烟测试）已经能用界面点击打完整局。
风险在界面时序：等到真正的决策点、选牌界面与奖励界面的嵌套、过幕。

## 做法

### 1. 原生侧：`nosl::Pilot`（`nosl/pilot.{h,cpp}`、`nosl/pilot_api.cpp`，库 `libsts2nosl_pilot.so`）

一个对象包住：同种子的影子 Env、actor 过滤器、原生前向（`nosl/policy_net`）。只有一个调用 `Next()`：

- 只有一个合法动作时返回它（与采样器的自动执行一致）；否则在 `nosl::Observe` + 过滤器的观察上跑一次前向，按策略分布抽一个动作。
- 返回这个动作（Env 的动作：种类、序号、目标、地图坐标）、选择请求的说明、动作之前的**公开状态摘要**，然后用这个动作推进影子。
- 不试动作，不展开未来，影子只被返回的那个动作推进。

`tools/nosl/nosl_pilot`：不带游戏把 `Next()` 一直调到终局，输出每一步。实机执行器对同一种子、同一权重、同一策略种子应当复现这份输出。

### 2. 游戏侧：Mod `tools/NoslPilot`

按 `AutoSlay` 的结构（房间处理器 + 界面处理器 + 等待/看门狗），把其中的随机选择换成 `Next()` 返回的动作：

| Env 动作 | 游戏里怎么做 |
|---|---|
| `MapMove(col,row)` | 点击地图上该坐标的 `NMapPoint` |
| `PlayCard(手牌序号, 目标)` / `EndTurn` | 像界面一样入队 `PlayCardAction` / `EndPlayerTurnAction` |
| `UsePotion` / `DiscardPotion` | `PotionModel.EnqueueManualUse` / `DiscardPotionGameAction` |
| `TakeReward(i)` / `Proceed`（奖励） | 点击该奖励的按钮 / 继续按钮 |
| 卡牌奖励的 `Answer` | 点击卡牌奖励界面上的卡牌或替代选项 |
| 其余选牌的 `Answer`（先张数、再逐张） | `CardSelectCmd.UseSelector` 注册的选择器一次性回答（`AutoSlay` 和 oracle 用的同一个入口） |
| `EventOption(i)` | 点击第 i 个事件选项 |
| `RestOption(i)` / `Proceed` | 点击休息点选项 / 继续 |
| `ShopBuy(i)` / `Proceed` | 购买该条目 / 离开 |
| `TreasurePick(i)` / `Proceed` | 开箱、点遗物 / 继续 |

每次在真实游戏到达决策点时，Mod 用游戏对象算同一行公开状态摘要（幕、层、HP、金币、牌组张数、遗物数、药水栏；战斗中再加格挡、能量、回合、
手牌顺序、三个牌堆张数、每个敌人的 HP 和格挡），与 `Next()` 给的比较。不一致就停下：写日志，不再操作，把游戏留给人。
`Next()` 报错（未移植内容、引擎错误）同样停下。这就是 F11 要求的“失败不伪装成正常结束”。

### 3. 隔离运行

`tools/NoslPilot/run_live.sh`：把正版游戏目录硬链接到 `artifacts/` 下的实例目录，放进 Mod 和原生库，使用独立的 `XDG_DATA_HOME` /
`XDG_CONFIG_HOME` / `XDG_CACHE_HOME`，`--headless --force-steam=off` 启动。**不往用户的游戏目录装 Mod，不读写用户的存档目录**；
全解锁进度只从用户档案复制一份到实例里。启动方式沿用仓库里已有的无人值守启动器（`external/CombatSolver/tools/run-unattended-test.sh`）的参数。

## 信息边界（如实说明）

- actor 的输入仍然只是 `nosl::Observe` + 过滤器的三张表，与训练完全相同；没有模拟、搜索或试动作回滚。
- 但影子 Env 靠**种子**和已执行的动作与游戏保持同步，所以承载它的进程持有完整种子，影子内部也有尚未公开的未来。
  这些没有进入网络输入（`nosl_obs_check` 检查过观察对隐藏状态不变），可是按整局计划 §10 的审计口径，“部署无隐藏未来输入”这一条**不能**靠影子方案打勾。
- 因此本任务的产物定位是：执行器（界面操作、时序、停机）加上一份实机里的逐状态参照。去掉种子依赖要靠游戏侧直接从公开对象编码观察（Q5-b），
  届时用影子给出的表逐决策对照（整局计划 I02 的“训练编码与实机编码逐状态对照”）。
- 人接管之后影子就失步了：本版本接管即永久停止本局的自动操作。存读档续局不支持。

## 验收（结果出来前固定）

1. **干跑一致**：`nosl_pilot` 的轨迹经 `oracle_replay` 在正版逻辑里重放，全部 identical（先做，不需要启动游戏）。
2. **实机整局**：至少 5 个 dev 种子，各从新开局到游戏结束界面，0 人工输入；每局的动作序列与同种子的干跑逐步相同，结束层数相同。
   全部尝试都报告；中途停下的局写明停在哪一步、摘要差在哪里。
3. **摘要**：每个决策点比较一次，报告比较次数和不一致次数。判“通过”要求不一致为 0。
4. **延迟**：`Next()` 的中位数、p95、最大值；一局的墙钟时间。
5. **阶段覆盖**：这些局里实际走到的决策种类列表（地图、战斗、奖励、选牌、事件、休息、商店、宝箱、过幕），没走到的写“未验证”。
6. 第一幕之后的内容大概率走不到（策略目前死在第一幕）。不为了覆盖去改 HP 或注入牌组；需要的话另开带标签的诊断运行。

## 预算

实机每个实例约 4 GiB 内存，与训练不能同时跑：只在训练队列的空档里测试，一次一个实例。
