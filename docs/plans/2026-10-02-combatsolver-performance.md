# CombatSolver 消费者性能优化

目标：降低实用首版搜索耗时，保持胜率、战损和路线合法性；Env API、游戏规则、
状态独立拥有、选择前缀和 SafeOutcome 语义保持不变。nosl/训练不在本轮。

前置：`b47cf9c` 已有21场五角色对照、34082例政策差分和完整门禁；
本轮沿用工作树，分支 `perf/combatsolver-env-2026-10-02`。

任务：
1. 保存首版二进制与固定输入，添加可关闭的消费者阶段计时和工作计数。
2. 测量状态转换、特征提取、结束回合预测、合法动作与保路成本。
3. 优化不可变分支哈希复用、请求内评分缓存、重复节点剪枝和只读提取重复复制。
   缓存仅保存值，不借用其他状态可变存储；选择态使用完整续接身份。
   后继缓存保存拥有型状态并深复制复用。允许Env内部Clone在无pending/choice/boundary时
   不保留已完成动作的无用base；不改变API、hash、快照或执行规则。
   对象池可改为小块拥有型存储，以减少clone分配；逻辑capacity/cursor、lowest-free顺序、
   hash/快照和活对象地址必须保持一致，并复验70,000引用及真实容量失败原件。
4. 同一机器串行比较旧版、新版和上游；验证所有原21场根、胜利、战损、完整路线。
5. 加入针对缓存/剪枝语义的差分合同，并在额外战斗/选择/用药配置上复核。
6. 更新消费者说明、README、路线图和执行报告，提交可审阅的改动。

验收：固定21场总耗时显著降低，以达到上游同量级为目标；全部获胜、
总战损不劣于首版，记录逐场变化。缓存开关在充足且相同节点预算下应得到
相同路线/最终完整hash/质量；阶段计时不代替质量验证。
运行搜索合同、政策差分与仓库完整 `scripts/check.sh`。性能测量不在CTest中。
不能以不同输入、降低搜索预算或修改游戏语义制造提速。

涉及：`search/combatsolver/*`、`tools/combatsolver/*`、`env/env.cpp`、`engine/sim/pool.h`、
搜索/克隆/容量合同、说明及报告。

完成记录：相同21场与125892展开节点87.632→46.576秒，路线/质量/完整hash全部一致；
上游34.820秒，仍约1.34倍耗时。15个A10精英/Boss部分路线探针、34082例政策差分、
57CTest/L2/L3/L4、6500张牌API/SDK和真实容量失败重放全部通过。
完整证据和缓存内存成本见[执行报告](../reports/2026-10-02-combatsolver-performance.md)。
