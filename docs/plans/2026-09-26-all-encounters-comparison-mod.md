# 全遭遇战与战士双求解器游戏 Mod

## 目标

以正版 v0.111.0 游戏源码和 oracle 为真值补齐全部正式遭遇战，再把 CombatSolver 与 `sts2sim` Env 作为两个可在单人战士实机战斗中运行的搜索后端，展示同一根状态下的结果和速度。

## 当前基线

开工时正式遭遇 90 个、已移植 39 个；MonsterModel 内容定义 126 个、已移植 46 个。此前的 `tools/dual_solver/compare.py` 只对比合成的首回合离线根，不能当作游戏内 Mod 或任意 live 状态的验证。

## 工作项

1. 按怪物及其 Power/状态牌依赖逐批移植 51 个剩余正式遭遇；每批用 L3 完整决策点与 oracle 对拍。明确登记失败和未移植边界。
2. 扩展 Env C ABI，让 .NET 游戏进程可在后台调用 C++ 搜索，并返回结构化根状态、动作和搜索耗时。
3. 制作独立比较 Mod：真实游戏加载后只处理单人战士，在主线程捕获稳定 live 根，再在后台运行 Env 搜索，同时读取 CombatSolver 的同根搜索结果；两边结果在游戏内可见，日志可导出。
4. 补齐 live 状态导入与严格根一致性门槛，包括牌组、遗物、药水、怪物状态、能力、RNG。根不一致时不得输出“同状态速度对比”。
5. 在游戏内实际加载 Mod，验证两个搜索后端都运行、根匹配、动作可执行，并记录同预算及工作量定义下的耗时。

## 验收

- 90 个正式遭遇全部可由 Env 进入，铁甲战士随机/定向策略对拍无状态分歧或明确的非遭遇内容边界。
- 比较 Mod 在正版游戏中加载，战士任意已支持战斗可独立启动两种搜索，界面显示根状态一致性、搜索耗时和首动作。
- 同一 live 根且两边完成搜索时，性能报告有原始毫秒数、预算、展开/rollout 数及条件；根不一致不宣称提速。
- `scripts/check.sh` 全门禁通过，Mod 游戏内运行记录与构建步骤写入报告。
