# L1：新策略形态的实机执行——策略包、直连模式修复与后幕界面

前置 main `b3779a5`。分支 `feat/nosl-l1-live-bundle`，产物只写 `artifacts/nosl-l1/`（开发期间的首批实机日志在 `artifacts/nosl-r2/live-*`，报告里注明）。完整高水平 Silent A10 与 Linux 成品目标不缩小；本项只处理实机执行这一条线上已经暴露的缺口。

## 为什么现在做

R1 之后被评价的策略不再是单个网络：战斗内是 X1，战斗外是“X1 的动作，除非局外价值模型认为另一个动作高出 margin”。原生前向和实机执行器（`tools/NoslPilot`）只支持单个网络。等模型练好再适配，会重蹈“训练编码与实机不一致到最后才发现”的覆辙。另外 Q5-a 之后实机执行器没有走到过第二幕，新策略已经能进第三幕。

## 范围

1. **策略包**：原生 actor（`nosl/actor.h`）除了单个导出网络，还能读一个文本策略包：战斗网络、可选的局外基础网络、可选的局外价值网络和 margin。规则与 `nosl.strategy_q` 的评价通路相同。C ABI 和 Mod 的调用不变（权重路径可以是策略包）。`python -m nosl.export_bundle` 生成策略包。
2. **一致性检查**：`tools/nosl/nosl_actor_check` 按采样器语义重放已记录的贪心整局，在每个多选决策上问原生 actor，与记录的动作行比较；重放始终跟随记录，一处不同不遮住后面的决策。
3. **直连模式修复**：直连模式（Mod 只读游戏对象、actor 路径上没有影子和种子）在新种子上暴露的问题逐个定位首因并修复，不放宽比较。
4. **后幕界面**：用能走到第二、三幕的留出种子在实机里跑影子模式（逐决策比较游戏侧编码与影子编码）和直连模式（逐动作与无游戏的干跑比较）。遇到不支持的界面，按正版源码补上，或如实列为缺口。

不在范围：暂停与人工接管的热键、带窗口运行、普通开局菜单与用户自己的档案、胜利结算（策略还走不到）。这些列在报告的缺口表里，另行登记。

## 验收（先于结果登记）

- 策略包规则：留出评价的两组轨迹（X1 单网络、R1 选中规则）各取 192 局，原生 actor 的贪心决策与记录逐个相同；不同的决策全部列出，不设容差。
- 实机：至少 8 个留出种子，其中至少 3 个的干跑进入第三幕。每个种子影子模式、直连模式各一局，真实 Godot 可执行文件、无头、隔离实例、游戏 Fast 速度与普通交互模式。每局要么打到游戏自己判定的终局且每个动作与干跑相同（影子模式另要求游戏侧编码与影子编码逐决策相同），要么停下并留下首因。全部尝试列表报告，停下的不算通过，也不隐去。
- 不修改用户的游戏安装、Mod 目录和存档；实例是 `artifacts/nosl-q5a/instance` 下的副本。游戏版本先核对为 v0.111.0（`41cef1ea`）。
- 记录每个策略决策的延迟（中位、p95、最大）与游戏进程峰值内存。
