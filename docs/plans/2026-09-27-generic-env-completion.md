## 1. 开发决定与完成范围

继续开发通用 Env 和 Random Foreseer 类预测 API。首批普通预览、模拟器房间恢复与原版语义回退已通过有限合同/回归，完整 Env/RF 门槛未通过。CombatSolver 历史代码冻结，除非用户重新明确要求，不会在 Env 完成后自动恢复。本计划不构成恢复旧移植的授权。

完成按固定版本和明确范围定义：

- 游戏 v0.111.0 的单人原版，五个角色，完整三幕对局及各原版地图变体、先古、房间和可达内容；升阶与官方单人修饰规则按内容清单逐项验收。
- 当前全解锁基准继续用于回归；真实 live 档案的解锁、纪元、初次运行及已见遭遇规则是需要补齐的 Env 语义，不能把用户档案强制视为全解锁来宣称完成。
- Random Foreseer v0.13.17 的单人预测能力必须能由公共 Env API 表达。公平模式、提示文本、Godot UI、搜索算法和部署由客户端实现。
- 多人、第三方新增游戏规则、不可达的调试/废弃内容不自动纳入。排除清单必须有游戏源码证据；原版效果能生成或触及的模型不能因无差分测试而被排除。

这里的“客户端只调用 Env”指：在上述版本与范围内，客户端捕获状态、调用通用接口、投影策略并展示结果。游戏升级或第三方新规则不在这项保证内。完成本计划不会自动解冻 CombatSolver，也不代表旧 Beam/专用 prediction ABI 成为公共 Env 能力。

## 2. 架构与公共合同

### 职责

| 层 | 提供内容 |
|---|---|
| C++ Engine | 正版规则、对象身份/寿命、全部 RNG、Hook 顺序、数值计算、房间和效果执行 |
| 通用 Env / C ABI | owned 分支、事务式预测、可恢复选择、合法动作、游戏查询、结构化结果、执行边界和可选事实追踪 |
| 独立 C#/Python SDK | ABI 版本/所有权/错误封装，通用快照与查询类型 |
| 游戏捕获适配器 | 在已定义静止边界捕获真实字段，冻结输入，映射稳定模型/FSM 身份；不调用游戏逻辑来执行搜索后继 |
| 客户端 | 搜索政策、评分、剪枝、状态键/历史投影、风险偏好、预算、UI、允许展示的信息和真实动作部署 |

### 需要形成的 API（设计要求，当前尚未全部实现）

1. **快照**：全部房间决策、嵌套奖励/事件和选择前缀的 `Capture/Validate/Restore`。选择保存静止根、原版操作描述、答案前缀；不尝试复制任意 C# async 调用栈。协议包含游戏/内容/模式版本及稳定模型身份；当前进程 runtime ID 输运与未来可持久保存协议明确区分。
2. **预测**：在同一 owned 分支上执行合法动作或有类型的原版操作，并指定停止边界。至少区分操作完成、下个玩家选择、下个战斗决策、敌方阶段结束、安全胜负点和完整房间结算。普通 `Step` 的变更规则、失败保证和纯 `Predict` 的不变保证分别写明。
3. **局外预览操作**：变牌、获取遗物、事件选项、生成/重掷奖励、商店购买及补货、休息效果、献祭。优先复用正常动作；悬停或预览尚未发生的操作时，提供带来源模型和上下文的明确假设分支，不添加任意内存写入接口，不另写一套随机算法。
4. **只读查询**：原版费用、目标、动态变量/计算值、意图、牌堆、球和能力，以及 Hook 计算所需原始事实。lazy getter 的写入隔离在私有分支；禁止以原 Beam 的字段筛选、终局保留计算或评分为 C++ 游戏语义。
5. **结果与追踪**：状态差分/生成对象/奖励/目标/伤害/资源变化、父子因果、来源实例与操作、稳定顺序、选择和执行停止原因。RNG 流/抽取及隐藏信息仅在特权诊断接口中返回；面向智能体的观测仍遵守隐藏信息边界。
6. **支持与失败合同**：模型、方法和条件路径的覆盖信息；明确 `Exact / NeedsChoice / Unsupported / Truncated / Invalid` 类语义。达到容量或执行上限不能伪装成精确结果；原根不被失败分支改变。需选择时把可继续分支交给客户端，未知原版逻辑必须明确报告。

追踪是独立、可关闭的 execution 数据，不把动态容器塞进 POD `GameState`。按步增量采集、对象退休后仍可解释的身份以及选择重放的去重必须有合同。性能验收同时测关闭追踪的引擎和启用追踪/ABI 的客户端成本。

## 4. Random Foreseer 功能验收矩阵

| 功能组 | 通用操作/查询必须覆盖 | 对拍检查 |
|---|---|---|
| 抽牌/重洗/Frozen Eye | 分支牌堆、抽取、shuffle、可见顺序 | 原始实例顺序、临时费用、RNG 及各抽牌 Hook |
| 生成牌/药水/随机目标/选牌 | 正版候选池与过滤、生成操作、pending choice | 候选顺序、实际结果、目标、答案后续和 RNG |
| 自动打牌/球/结束回合 | 连续效果、球被动/激发、随机目标、来源追踪 | 执行顺序、每笔损伤/资源变化、生成和选择、结束点 |
| 变牌/遗物拾取 | 选定实例、来源原版效果及奖励/变牌 Hook | 候选排除、升级/附魔、遗物袋、输出及 RNG |
| 事件/隐藏牌位/下一幕 | 事件实例状态、选项、后续奖励、预生成队列 | 精确选项可用性、随机结果、位置及选择分支 |
| 商店补货/奖励重掷/献祭/休息 | 库存与黑名单、获取后 Hook、连续奖励偏移 | 费用、库存、遗物袋/概率状态及随机流顺序 |

需要用户选择时不能代选而宣称唯一预测。公平展示策略由客户端使用可见性标签和选择结果构建。RF 的 approximate mirror/inference 风险处理不作为 Env 规则；Env 以正版语义和明确支持状态验收。

## 5. CombatSolver 历史冻结边界

本计划不设 Env 完成后自动恢复 CombatSolver 的门槛。旧搜索代码、专用 Beam 与 `sts2_combat_prediction_*` ABI 冻结并归档；只有用户后续重新明确要求时，才开始新的相关工作。Env/RF 阶段或验收结果本身不触发恢复。

M3 普通参考 ISMCTS 仍保留为 Env 外部消费者示例和回归消费者。它与旧 Beam 移植、专用 prediction ABI 分开；旧 Beam/专用 ABI 均不列为公共 Env 能力。完整 Env 与 RF 功能完成后，公共 Env 可由不同客户端使用，但不会因此自动恢复历史 CombatSolver 项目。
