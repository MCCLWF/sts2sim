# 静默猎手 A10 整局 NoSL：需求与探索计划

- 日期：2026-10-03。
- 状态：需求与研究计划已形成；训练、模型与整局部署尚未实现。
- 用户目标：静默猎手（Silent），A10，覆盖战斗内外，最终在当前 Linux 游戏中实际操作。
- 规则基线：正版 v0.111.0，单人、全解锁老档案；版本变化另作兼容性验收。
- 研究依据与当前能力边界：[研究报告](../reports/2026-10-03-silent-a10-nosl-research.md)。

## 1. 哪些已经确定，哪些仍须探索

**确定的是产品目标、信息边界、规则保真和验收方式。训练算法、网络结构、环境后端与开发顺序保持开放。** 后续每项工作应围绕一个可回答的问题开展小实验，再决定下一步；本计划不是必须照次序完成的实现清单。

| 类型 | 决定 |
|---|---|
| 确认需求 | Silent A10 的完整正常跑局，包含所有单人决策阶段；上线 NoSL；Linux 实机执行 |
| 当前工作假设 | 用 CombatSolver 示范初始化，再通过真实随机性下的强化学习改善，是值得首先比较的候选 |
| 未定方案 | BC/PPO 或其他学习方法、教师投入、单模型/多头/分层策略、记忆结构、课程、奖励、批处理方式、C++ Env / 原版 DLL 的训练分工 |
| 已有工程底线 | 游戏规则只以源码和正版 oracle 为真值；不能通过修改规则让策略更容易获胜 |
| 非当前承诺 | 五角色同时训练、多人、部分解锁档案、指定胜率、指定训练时长、搜索器与上游完全一致 |

首个学习目标就是 Silent。Ironclad 可以用于已有工具的回归或故障定位，不作为“必须先练成”的前置里程碑。A0 可用于验证学习闭环或课程，不要求先把 A0 练到某种完成状态再接触 A10。

## 2. 最终产品与 NoSL 合同

### G1：完整跑局

从正常新局开始，策略自主完成选路、战斗、构筑与资源管理，直至游戏确认胜利或死亡。A10 的成功以原版终局判定为准，包含 DoubleBoss 的第二个最终 Boss；不能将第一幕结束、单场胜利或第一个最终 Boss 胜利计作完整成功。

### G2：上线只做策略推理

本项目把 NoSL 明确定义为：**部署时根据当前公开观察与公开历史做决策，不调用模拟器展开未来，不搜索动作树，不在游戏中试动作后回滚，也不通过读档挑选更有利的未来。**

- 模型可以学习“预计长期收益”，也可以推理价值头；这与运行未来轨迹的预测接口不同。
- 离线训练可使用 Env、原版引擎、教师搜索、训练快照及特权 critic；这些不能进入部署 actor 的信息或执行路径。
- 游戏逻辑正常执行已选动作不属于模拟搜索。正常保存恢复可用于继续同一局，不能成为比较未来的工具。
- 官方 NoSL 结果不得混入隐蔽的 CombatSolver/MCTS/RF 回退。若使用可观察规则回退，须明确记录并单独评价。

### G3：面向高水平操作的目标

主要质量指标是正常规则下 Silent A10 的整局胜率与稳定性，兼顾决策延迟和资源成本。局部战损、教师动作一致率和训练奖励只能作诊断，不能代替整局质量。

现在没有证据可以承诺具体胜率。先测基线，再在每轮实验开始前登记可接受的提升、成本和不确定性；禁止结果出来后才改变成功标准。

## 3. 功能需求：覆盖每种决策

| ID / 场景 | 必须支持的观察与行为 | 验收要点 |
|---|---|---|
| F01 全局上下文 | 当前角色、A等级、幕/层、HP/最大HP、金币、牌组、遗物及公开计数、药水槽和药水；已知跑局历史 | 区分正常游戏与训练注入；不暴露未揭示房间内容或 RNG |
| F02 地图 | 玩家可见拓扑、当前位置、可到达节点、公开房间/已揭示 Boss 信息；选择合法下一节点 | 支持读档和特殊地图；按实际显示的信息编码 |
| F03 战斗 | 手牌实例与公开属性、费用/资源、敌人状态、当前公开意图、力量/状态、遗物与药水；出牌、目标选择、用/弃药水、结束回合 | 单体/群体、无目标牌、同名不同实例、触发与战斗结束均按原版语义 |
| F04 牌堆与历史 | 公开可检查牌堆内容；抽牌堆无序多重集；已公开放到顶端的牌和敌人公开行动历史 | 不能把引擎抽牌顺序作为输入；公开已知前缀失效时正确清除 |
| F05 奖励/构筑 | 实际展示奖励、卡牌与替代选项；领取、选牌、跳过、重抽等原版可用操作 | 正确处理嵌套奖励、自动完成和奖励可用性变化 |
| F06 商店 | 公开商品、属性、价格、买得起与否、移除服务和公开限制；购买、移除、离开及后续选择 | 买不起的展示商品也属于观察；不把金币不足等同商品不存在 |
| F07 事件/先古 | 当前展示文本/选项与公开效果、相关牌组/资源；选项与嵌套选择 | 允许公开规则知识；不提前读取隐藏随机结果 |
| F08 休息点 | 原版可用休息/升级/特殊选项和后续候选 | 不硬编码只有治疗与升级；保持嵌套顺序 |
| F09 宝箱/过幕 | 展示的宝箱与领取/选择流程，正常过幕、奖励及终局确认 | 覆盖特殊来源奖励和过幕续接；不能提前停止评价 |
| F10 通用 Choice | 选牌、弃牌、消耗、生成、排序/放顶、单选/多选等实际选择请求 | 支持数量范围、顺序、取消/确认条件与多级选择 |
| F11 异常与接管 | 不支持内容、过期动作、模型失败、停止/恢复与日志 | 明确原因，保持当前游戏可恢复；失败不能伪装成正常死亡或胜利 |

本表要求功能覆盖，不要求每个阶段一定拥有独立模型。游戏动画等无决策阶段应等待正确决策点，不制造无意义的学习动作。

Silent 跑局可能通过原版机制生成跨职业卡牌或特殊内容；范围按实际可达状态定义，不能仅按 Silent 初始牌表裁剪词表与合法动作。新版本/未知内容须显式报告兼容性缺口，不静默映射成另一张牌。

## 4. 观察、动作与信息边界

### I01：actor 输入必须可由玩家公开信息构成

允许屏幕/可检查界面展示的数据、公开静态规则，以及公开历史推导的数据。排除 RNG 状态、完整 run seed、实际未公开抽牌顺序、未来敌方随机选择、预生成遭遇/奖励/遗物队列及未揭示内容。

实例身份可用于关联牌与动作，但编码不能通过引擎全局 UID、生成次序或状态 Hash 间接泄漏隐藏内容。公开局部引用与模型特征应分开。遗物/事件内部字段只有在玩家可观察或由公开历史推导时才能成为 actor 特征。

固定公开状态、改变隐藏状态，actor 观察与公开可用动作应保持一致；存在合法的公开差异时须说明来源。该检查也适用于记忆、归一化、数据标签、调试字段与价值辅助输入。

### I02：训练与部署共享可检验合同

- 观察有 schema 版本、内容版本、字段语义、可见性与缺失值规则。
- 动作能准确绑定到产生它的观察/决策版本；目标、卡牌实例和选择候选有稳定关联。
- 部署前做训练编码与实机编码的逐状态对照；采用 C++/C# 双编码、共享规范、直接捕获或其他实现均可。
- 合法动作与 mask 在采样和训练更新中语义一致；嵌套选择保持原版合法数量与顺序。
- 可变牌组、敌人、候选与历史不能静默截断。若模型容量有限，采用明确可验证的表示/分解方案；不修改游戏容量来迁就网络。
- 现有公共查询可复用。当前 `Observe()` 的简化向量不是完整学习合同，不能仅因接口存在就视为就绪。

### I03：保留必要公开记忆

是否采用 RNN、Transformer、历史摘要或其他结构由消融实验决定。但已知放顶、公开敌方历史和长期资源上下文不能因无记忆网络方便而直接丢弃。训练重置、战斗转换和读档恢复要有明确记忆语义。

## 5. 环境正确性与数据质量

### E01：不改变原版规则

同种子同动作的环境结果仍须与正版一致，包括 RNG 与选择续接。强化学习探索到的新路径要持续抽样回放到 oracle/实机，比较动作合法性、公开观察、关键结果与终点；定位首个分歧并保存复现材料。

现有全绿门禁和高 HP 多幕路线提供有限证据，不能替代正常资源 Silent A10 的新策略轨迹验收。训练越强、内容越深，越要扩展其实际访问分布的对拍。

### E02：结束类型必须分开

| 结束类型 | 数据处理与评价 |
|---|---|
| 原版胜利/死亡 | 真实 terminal，按任务目标计分 |
| 合法轨迹上的训练采样时间界限 | 标记 truncation，按所选算法正确处理 bootstrap 与剩余任务 |
| Unported、语义分歧、捕获/通信/执行故障 | 隔离受影响数据，保存原因；不得默认作正常 terminal 或可信 bootstrap |
| 人工课程或场景结束 | 标记课程定义，不计入完整 A10 胜率 |

失败数量、发生阶段和排除规则必须公布。只报告成功完成轨迹会产生选择偏差；应同时报告全部尝试的系统完成率及合格轨迹的策略表现。

### E03：可复现且不泄漏的记录

每份数据/实验至少记录：游戏与环境提交、教师/策略版本、schema、难度、初始状态来源、种子分组、动作与结果、结束类型、故障、耗时与资源。诊断可保存特权状态，但须与 actor 数据隔离，保证加载器无法误读。

训练、调参和最终测试划分独立。相同 run seed 的不同预算、难度、路线或生成场景不能无意跨入最终留出集。统计样本单位应以独立跑局/根状态为主，不能把同一局的上千步当成上千个独立胜率样本。

## 6. 教师使用：可用，但不设为能力上限

CombatSolver 只提供战斗教师，不能替代选路、构筑、商店与事件的整局策略。其单世界路线使用特权未来，且受启发式与停止条件影响；它既不是公开信息下的最优答案，也不是数学意义上的性能上界。

候选用法包括低成本路线行为克隆、动作分布/价值蒸馏、学生状态再标注、离线专家迭代和诊断对照。首个候选可以是少量路线初始化，不要求先构建昂贵的多世界教师。

### D01：教师采集必须先验证可行性

- 用真实或合理生成的 Silent 牌组、遗物、药水与多幕战斗试采，记录预算、停止原因、秒数、RSS、路线长度与可重放率。
- 新局、生成场景、中途状态恢复和自动执行是不同能力，不能假定现有无 Godot harness 已支持任意根批量标注。
- 先验证路线能在选择的训练后端执行、候选/目标能正确对齐，再扩大数据集。
- 不强制与原生移植搜索完全一致。只有影响教师数据、环境验证或学习结果的差异才成为当前优化目标。

### D02：数据质量与投入由实验决定

教师动作在隐藏未来变化时可能变化。作为预训练信号可以接受，但应比较其对最终公开信息策略的净收益，不能用模仿准确率单独验收。

若使用教师，比较低成本无示范基线与教师初始化的闭环表现，并抽查预算变化、复杂牌组与明显劣质路线。是否过滤示范、增加预算、做 fair ensemble、DAgger 或小实例精确参照，取决于收益/成本证据。将搜索价值对多个世界平均也不自动解决搜索内部继续预知未来的问题。

生成牌组只是初始分布候选。后续数据需要包含当前整局策略实际构筑出的牌组和资源状态，避免只学会起始牌组或人工强牌组。

## 7. 学习方案：开放比较，而不是指定算法

| 候选 | 可能价值 | 必须回答的问题 |
|---|---|---|
| BC/蒸馏后接 PPO 等在线 RL | 先获得可用操作，再通过实际随机性和长期回报改进 | 示范是否有效；价值初始化/切换是否稳定；是否优于相同总成本的直接 RL |
| PPO 等在线 RL 直接训练 | 无教师依赖，学习目标直接来自环境 | 探索、稀疏奖励与样本成本是否可承受 |
| DAgger / 学生轨迹再标注 | 减少训练数据与部署状态的分布偏移 | 原教师能否恢复这些根；标注成本与特权标签偏差是否值得 |
| 离线专家迭代 / AlphaZero 类搜索训练再蒸馏 | 用学习模型改善离线搜索/标签 | 如何处理随机与部分可观测性；去掉部署搜索后是否仍有效 |
| 其他离线、在线或混合 RL | 如果前述候选成本/稳定性不合适，提供替代 | 合法动作、数据分布、离线偏差、资源成本与 NoSL 验收是否满足 |

原版 AlphaZero 在训练和对弈时都搜索，不能直接作为 NoSL 成品方案；它的思想可用于离线训练。任何候选在部署移除搜索后都需要重新评价策略本身。

### L01：战斗与全局的组织方式待比较

单策略、共享编码多头、独立战斗/全局策略及分层策略都可候选。重点验证战略决策稀少、长回报和阶段分布不均是否阻碍学习，不能仅按动作数量合并梯度。

如果采用分层：定义层间状态、奖励、折扣、时间跨度和更新频率。跨一场战斗的全局动作属于变长时间间隔，不能无说明地按每张牌折扣。共享编码器更新可能改变“冻结”的战斗策略；冻结范围必须包含影响它的所有参数，或将这种变化纳入实验。

### L02：奖励服从整局目标

战斗战损、楼层进度、击杀或牌组质量可以是课程/辅助信号，须说明它们如何影响真实目标。药水、HP 与成长的价值依赖后续局势，不能永久固定为单场最少战损。

可探索由整局价值评估战后状态、潜势奖励塑形等方法，但不能只优化一个不断变化的预测分数而丢掉实际胜负目标。奖励与折扣版本要固定在一轮可比较实验内；采用潜势塑形时明确其终点与折扣条件。

### L03：初始化、稳定性与信息隔离

BC 后 critic 预热、逐步减弱 imitation loss、KL 约束、回放混合等是待测稳定手段，不保证有效。公开信息 actor 可配训练期特权 critic；必须检验隐藏未来没有通过输入、共享计算、教师特征或部署依赖进入 actor。

训练环境按不同合法初始种子执行实际随机结果，已可用于无搜索 RL；不要求先修改 `Determinize()`。若需要同一观察下重采样隐藏世界，则另定义保留公开历史和已知牌顶的正确合同，当前方法不能直接当完整 belief sampler。

### L04：难度与分布迁移

A0 学到的参数可复用，不需要从零重训；但 A0 表现不能保证 A10 质量。A10 累积规则、敌人强度与双 Boss 会改变资源管理和状态分布，通常需要对应数据、训练或微调。

可比较直接 A10、较低难度起步后迁移、混合难度与自适应课程。A10 必须早期进入诊断集合，防止低难度代理目标主导设计。是否扩充模型容量由迁移与瓶颈证据决定。

## 8. 性能与资源需求

### P01：测完整学习流水线

分别计量环境推进、观察/动作编码、模型推理、Python/进程通信、reset、数据搬运、训练更新和 oracle 抽查。报告有效决策/秒、完整跑局/小时、GPU利用率、CPU线程利用率、RSS/显存峰值及失败率。

克隆+一步的微基准、搜索节点数和教师 gRPC calls/s 不等于 PPO 吞吐。PPO 本身不要求每一步克隆根状态。

### P02：并行可用性优先用实验确认

独立环境采样已有多线程潜力；同一场启发式搜索的成员并行只对当前少量任务有效。后续可比较原生 batch、线程池、进程池、持久缓冲与异步采样，不预先指定最佳方法或承诺线性加速。

共享的是只读内容和必要批处理，状态、RNG、选择续接与历史必须独立。网络推理批量与环境批量可分别设计，不能以吞吐为由改变动作语义或混淆 episode。

### P03：当前机器需先做容量试验

研究时检测到 RTX 5060 Laptop GPU，约 8 GiB 显存；系统内存约 14 GiB，swap 已用约 3.5/4 GiB，系统盘剩余约 16 GiB。这是当时快照，不是固定运行余量。

先测一个小模型、少量环境及代表性教师根，确认 GPU 软件栈、真实峰值和有效吞吐；再确定并发、数据保存、训练规模与耗时预算。不能由 GPU 型号推断已经能训练某种大模型。

数据集与 checkpoints 应有容量估计、保留与回收策略；原始失败证据和最终评估清单应可恢复。本计划不授权清理用户现有资料，也不要求先生成大数据集。

## 9. Linux 实机部署

### R01：整局执行能力

部署需取得与训练合同一致的公开观察，推理合法动作，并通过游戏允许的操作执行战斗和所有局外流程。模型运行库、C#/C++ 分工、通信方式与包装形式待选。

现有 Mod 自动执行原版 CombatSolver 战斗路线，不等于已经有整局 NoSL 执行器。局外捕获也不等于局外动作已经可执行；应对 F01–F11 建立逐项 live smoke/回放证据。

### R02：时序与可靠性

- 等待真实决策点、UI/效果稳定与必要主线程调度；动作执行前检查决策版本和合法性。
- 异步推理产生过期动作时丢弃并重新观察，不能在变更后的界面盲目执行。
- 支持取消、暂停、人工接管与故障日志。普通继续保存状态不能提供分支比较。
- 包装含模型/schema/游戏版本、依赖与使用方法；与已有搜索比较功能的实验结果分开。
- 部署可直接使用公开游戏对象，不强制导入整个 run snapshot 到 Env。只有所选方案确实需要时才扩展导入。

延迟预算由本机试验后确定并写入验收配置，报告中位数、p95 和最慢决策；上线应具备用户可接受的连续操作体验，不用“没有搜索”代替延迟测量。

## 10. 评价合同

| 维度 | 必须记录/比较 |
|---|---|
| 主要质量 | 正常资源、无注入、未见测试种子的 Silent A10 完整胜率；置信区间与实际样本数 |
| 过程质量 | 各幕生存、死亡原因、关键 Boss、HP/药水使用、卡牌与遗物分布、不同构筑表现 |
| 系统资格 | 全部尝试数、正常结束数、Unported/分歧/执行失败数、非法/过期动作、阶段覆盖 |
| 学习贡献 | 简单可观察启发式、纯 BC、候选 RL；同等或明确标示不同训练成本 |
| 教师诊断 | 战斗教师质量/预算、示范重放率；特权教师不能作整局公平胜率对手或严格上界 |
| 资源/响应 | 总生成与训练成本、吞吐、CPU/RSS/显存、模型大小、实机推理延迟 |
| NoSL | 部署 actor 输入审计；模拟/搜索/试动作回滚调用为零；所有回退与接管可追踪 |

调参集与最终测试集分开，并预先冻结评价规则。有限计算时先做小规模诊断，但给出不确定性；扩大最终样本由目标提升幅度和成本决定。关键结论尽可能跨多个训练随机初始化验证，不能将单次训练的偶然成功称为稳健结论。

注入 HP、指定遗物、生成牌组、特权输入学生都是有用消融/诊断，结果必须带标签，不能并入正常 A10 胜率。

## 11. 如何一步步探索

以下是问题门，而非必须依次实现的架构。可并行独立测量，也可因证据返回前一问题；每次只投资足以回答当前问题的工程。

| 问题门 | 最小可回答实验 | 决策依据 / 可能下一步 |
|---|---|---|
| Q1 基础可用吗？ | 核对观察/动作、少量 Silent A10 场景、原版重放、teacher/root 可恢复性与机器流水线试测 | 明确可复用接口、关键缺口；选择小试后端和范围，避免先搭完整训练平台 |
| Q2 能形成学习闭环吗？ | 在有限但明确分布上让一个合法策略采样、训练、闭环评价；覆盖必要 Choice | 若不能学，先定位观察/奖励/合法性/实现问题；若吞吐不够，再针对实际瓶颈批处理 |
| Q3 教师是否值得？ | 有/无少量示范、教师预算抽查、BC 后继续学习、A0→A10 或直接 A10 的成本比较 | 决定示范规模与稳定手段；低收益时减少教师投入，不因已有移植而继续扩展搜索 |
| Q4 整局组织和信用分配怎样？ | 在真实跑局分布上比较候选策略组织、战略采样与奖励处理 | 仅在梯度失衡/长期信用证据出现时增加分层等复杂性；补真实后期路径差分 |
| Q5 成品满足目标吗？ | 正常 Silent A10 留出整局 + Linux 实机完整回路，审计 NoSL 和编码一致性 | 报告质量、限制与未达标项；明确是否继续训练、修环境、改模型或调整下一实验 |

### 每轮研究/开发任务的固定交付

1. 写清问题、假设、最小改动、预算、对照与预先确定的判据。
2. 记录基线提交、版本、数据划分和结束语义，保留失败复现材料。
3. 实验结束报告结果、成本、误差、未验证范围及下一项建议。
4. 若推翻假设，允许停止该路线；不能将实验性选择偷偷升级为永久需求。
5. 按仓库规则使用任务计划、分支和报告；规则/代码合并跑相应检查与完整主线门禁。

不得把试验建议中的某个样本数、教师预算、课程阶段或网络层数当永久门槛。先小试估计方差/成本，再固定本轮预算；结果可复现且可比较比固定路线更重要。

## 12. 首批仍待回答的问题

| 问题 | 当前判断 | 需要的证据 |
|---|---|---|
| 原版 DLL 还是 C++ Env 更适合训练？ | Env 独立并行有潜力，DLL 规则与现有教师直接；后端可混合 | 真实采样流水线成本、恢复能力、规则风险与观察一致性 |
| 要先做原生 batched step 吗？ | 不自动列为第一项；已有 VectorEnv 不等于原生并行 batch | 无克隆推进+完整编码+推理的分项 profile |
| 两个策略是否一定优于一个？ | 不能由战略动作少直接得出结论 | 采样/梯度平衡、学习稳定性、共享与冻结消融 |
| BC 是否应使用大量教师标签？ | 小规模初始化是合理候选，大规模投入未获证据 | 示范的闭环收益、预算质量、学生分布与成本 |
| A0 训练能否直接玩好 A10？ | 可迁移参数，效果不保证；最终训练/评价需覆盖 A10 | 固定留出 A10 的迁移、微调与混合课程比较 |
| 是否需要公平多世界教师？ | 非默认前置；昂贵且公平性需额外合同 | 便宜示范+RL 的不足、ensemble 净收益和成本 |
| Env 还能带来优势吗？ | 优势候选是大量保真采样、重放/故障定位与独立并行 | 训练吞吐/正确性实测，而不是旧搜索对齐程度 |
| 哪些后期内容首先补？ | 按 Silent 新策略访问频率、严重程度与可复现性排序 | 正常 A10 轨迹、oracle 首因及实际失败分布 |
