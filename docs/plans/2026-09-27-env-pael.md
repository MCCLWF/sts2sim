# Generic Env: Pael initial options

Date: 2026-09-27.

## Goal

Port v0.111.0 `Pael.GenerateInitialOptions` into the generic Env while preserving the three pool materializations, candidate order, eligibility conditions, mutable relic allocation order, and event-local RNG calls.

## Source behavior

1. Construct PaelsFlesh, PaelsHorn, and PaelsTears in pool 1 order, then draw one option.
2. Construct PaelsWing. Append PaelsClaw when at least three deck cards satisfy `Goopy.CanEnchant`; append PaelsTooth when at least five deck cards are removable. Execute `list.AddRange(list)`, duplicating every current entry with the same `EventOption` state and relic reference. Append PaelsGrowth, then draw one option.
3. Construct PaelsEye and PaelsBlood. Append PaelsLegion only when `Player.HasEventPet()` is false, then draw one option.

`Goopy.CanEnchant` delegates to the base enchantment predicate and requires the Defend tag. `HasEventPet` checks relics whose `AddsPet` override is true and then the deck's Byrdonis Egg; v0.111.0 has `AddsPet` overrides on Byrdpip and Pael's Legion.

## Implementation

- Add `game/Models/Events/Pael.h` with the three pools and three ordered `Rng().NextItem` calls.
- Use `AncientRelicOption` for each candidate, retaining the source relic allocation and ancient-event callback behavior.
- Implement the Goopy eligibility test from `BaseCanEnchant` plus the Defend tag.
- Implement the event-pet condition from the two source `AddsPet` relic IDs and Byrdonis Egg. Do not use the broader shared helper, which also treats `spawns_pets` relic data as sufficient.
- Duplicate the second pool from a snapshot of its pre-duplication size, preserving the self-`AddRange` result without constructing new relic options.

## Acceptance

- Candidate order and conditional additions match the source.
- The second pool duplicates Wing, Claw, and Tooth entries already present before adding Growth.
- The three pool choices use the event-local RNG in source order.
- No relic effects are approximated; existing generic model dispatch remains responsible for unsupported relic behavior.
- Only the new event header and this plan/report are edited; generated files, build, and oracle are left to the integrating agent.
