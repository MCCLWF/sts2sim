- 前置：Q4-k 的最佳 X1 checkpoint 已存在，features 3、actor_filter 1；dev 18.66 层、65/200 进入第二幕、0 胜。云实例 SSH/CUDA 张量运算通过。

## 问题与最小改动

已有逐牌特征带来过增益，但当前策略在构筑、升级和第二幕仍弱。显式汇总公开牌组组成，能否在相同短训练预算下胜过继续原设置？

新增 features 4：仅使用公开 `Deck` 多重集 token（升级等级 n0、张数 n1）与 checkpoint 的静态牌面表。原始向量是牌面数值总和（14）、平均值（14）、牌面标志数量（42）、牌组张数和升级牌张数（2），共 72 项，经过既有 numeric 转换和线性层加到全局 token。没有 Deck token 的战斗观察不启用这层。新层从零初始化；观察 schema、规则、奖励与合法动作保持现有合同。

同时补齐原生前向和导出，保持 features 1–3 兼容。增加显式 `--reset-optimizer`，两个实验臂都重置 Adam 并在模型构造后重置训练 RNG，避免新增层导致优化器状态与初始采样 RNG 的不对称。

## 实验与预先判据

- 两臂都从同一 X1 checkpoint 出发：C 为 features 3，D 为 features 4。学习种子 2，同一训练前缀、同一批训练 seed，两个臂串行运行。
- 每臂 5,000,000 决策，硬时间上限 1,500 秒；6 个采样进程、每进程 80 局、rollout 64。其余设置照 X1：HP 潜势 0.2/70、gamma 1、boss-damage 0.3、lr 0.000133、target-kl 0.01、entropy-out 0.05、actor_filter 1。
- 2,500,000 和 5,000,000 附近保存快照，用现有 2,000 个 `NQGRDY` 种子贪心评价；保留逐 seed 原始结果和全部故障。最终臂间使用相同 seed 的层数差，给出均值、标准误和 95% 区间。
- **初步有效**：D 最终比 C 平均至少 +0.5 层，配对 95% 区间下界 > 0，进入第二幕比例不低于 C，且 D 不低于起始 X1。若未满足，如实报告阴性；不扩大训练。
- 有效才运行 D 的 dev 200 局及至少 30 条新轨迹正版回放；未有效仍运行最终模型的导出/前向对照，确保代码交付可用。
- 单个学习种子只能支持探索结论，不能声称稳步进步、高水平或最终留出胜率。本轮不使用 `NOSLTEST`。

## 必要验证

1. 真实观察：features 3 → 4 零初始化前向完全一致，Deck 多重集张数展开等价、token 重排/填充无影响；用真实牌面表检查总和和均值。
2. 有非零新增层的 features 4 checkpoint 与 C++ 前向对照，运行既有 `check_policy_net.py`；旧 features 3 对照继续通过。
3. 云端运行固定基线与两个短训练臂；报告平台版本、确切源码、配置、原始结果和失败分类。
4. 代码合入前运行完整 `scripts/check.sh`；构建限制本地 2 线程，不与本地大型作业并发。
