# R12：实机里肉眼可见的几处毛病——量出来，加守卫规则，整局验证

前置：分支 `fix/nosl-steam-runtime-abi`（`847f1a6`，另一会话做的 R5 实机 Mod，已过门禁，尚未合入 main；main 是它的祖先）。本项分支 `feat/nosl-r12-visible-defects` 叠在它上面，产物只写 `artifacts/nosl-r12/`。完整高水平 Silent A10、公开历史与 Linux 成品目标不缩小；部署只做策略推理。全程本机。

## 依据

用户 2026-10-11 在真实游戏里看到的：有药水必用、不看时机；商店买一大堆；买了药水又扔掉；战斗奖励不领。在 G6 采集数据里核对（进阶 10，7905 局，只看非探索决策，约 100 万个局外决策）：

| 现象 | 数据里的次数 |
|---|---|
| 商店里扔药水（药水栏满时） | 2387 次 / 9883 次逛店（约四分之一的逛店） |
| 奖励界面、地图、事件里扔药水 | 227、130、61 次 |
| 药水栏满时还买药水 | 1393 次 |
| 买药水 | 8020 次（每次逛店 0.81 瓶，与买牌 8608 次相当） |
| 买删牌服务 | **4 次** |
| 每次逛店买几样 | 平均 1.87，三样以上占 19%，离店时平均剩 47 金币 |
| 离开奖励界面时还留着金币 / 遗物 / 药水 | 311 / 17 / 50 次（约 4% 的局留过金币） |

“有药水必用”此前已知（R1 试过“留到 Boss”的脚本，净效果约零，当时战斗策略弱得多）。这些都是基础策略 X1（PPO）留下的习惯，表规则和把握规则不管这些决策。

## 问题

对每一处，加一条只读公开观察、放在所有规则之后的守卫（`python/nosl/guards.py`），整局结果变不变？合在一起在留出集上是否成立？

## 做法

守卫（`--guards`）：`nodiscard`（有别的动作就不扔药水）、`nobuyfull`（药水栏满不买药水）、`nopotionbuy`（完全不买药水）、`takerewards`（奖励界面上还有金币、遗物、或有空栏时的药水就不离开）、`hold=X`（非精英非 Boss 的战斗里，HP ≥ X 且药水栏未满时不用药水）、`removefirst`（商店有删牌且牌组里还有未升级的基础打击 / 防御就先买删牌，删打击优先）。被禁的选择退回到当场策略评分最高的其他动作。

参照臂 `ref` = R5 的最终组合 + R10 确认的战斗规则（`m40b`，margin 0.05）。单守卫各一臂：`d`（nodiscard + nobuyfull）、`t`（takerewards）、`h5`（hold 0.5）、`h3`（hold 0.3）、`npb`（nopotionbuy）、`rm`（removefirst）。每臂在 `NR12TUNE`（进阶 10，4096 局）和 `NR12ZERO`（进阶 0，2048 局，旁证）上各评一次，对 `ref` 配对。

启动前冒烟（NR6TUNE 前 256 局，不是登记的臂）：不带 `--guards` 时 256 局动作与旧基线逐局相同；各守卫都触发、无截断。

## 种子

`NR12TUNE`、`NR12ZERO`、`NR12EVAL`（留出，进阶 10，4096 局，跑一次）。都没有用过。

## 判据（先于结果登记）

- **纠错类守卫**（`d`、`t`）：纠正的是明摆着的浪费，只要单臂不是显著有害（配对差的 95% 上界 ≥ 0）就进组合。
- **取舍类守卫**（`h5` / `h3` 取好的一个、`npb`、`rm`）：进阶 10 调参集上结果目标配对差 ≥ +0.01 且 95% 下界 > 0 才进组合。
- 组合由脚本按上面两条自动拼出，在调参集上再评一次，然后在 `NR12EVAL` 上与 `ref` 各跑一次。**确认**：留出上配对差的 95% 上界 ≥ 0（组合里只有纠错类时），或 95% 下界 > 0（组合里有取舍类时）。
- 进阶 0 只作旁证。全部尝试、通关、死亡、截断、故障都报告；每个守卫每局触发几次一并报告。
