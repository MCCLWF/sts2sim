# Necrobinder v0.111.0 completion plan

## Goal

Complete the single-player Necrobinder path in the general C++ Env from baseline `59b51ec54a52b5069a56d05c768b35f81e950776`. Implement the full 91-card pool, eight relics, character setup and unlock gates, Osty and its summon/revive/damage behavior, directly related Powers, generated/token/status cards, SoulsPower enchantment, choice behavior, reward/pool integration, and cross-turn/run persistence. Keep the three Necrobinder potion models owned by the parallel `feat/shared-cards-all-potions-v0110` task; this branch defines their pool/use validation contract and records the pre-merge dependency.

## Source audit completed before implementation

The source inventory is in [`docs/audits/necrobinder-v0110-source-inventory.md`](../audits/necrobinder-v0110-source-inventory.md). It enumerates all 91 card IDs in `NecrobinderCardPool.GenerateAllCards`, all eight relic IDs, every declared model override from `data/content.json`, and scans the original C# bodies for branches, loops, generator/selection/pile calls, and RNG call sites in source order. It records character setup, five epoch unlock classes, generated Soul, the directly referenced power graph, Osty command/model, SoulsPower, and the external potion contract. Implementation decisions remain grounded in the original `src/Core` methods and Oracle comparisons.

## Work sequence

1. **Resolve cross-model contracts**
   - Compare baseline engine semantics with `OstyCmd`, `Osty`, all referenced Power methods, Necrobinder card/relic bodies, and source-driven epoch filters.
   - Identify each required generic hook, command, state field, generated card/factory path, choice prefix, and Oracle surface before editing it.
   - Send exact shared API changes to the run coordinator and potion-task owner before landing shared state, hook, factory, or Oracle edits.
2. **Implement model graph**
   - Add the complete Necrobinder card set and preserve each original upgrade, dynamic variable, keyword, targeting, hook, condition, loop, and generated-candidate order.
   - Add each missing Power and all eight relics, plus source-supported Osty/summon/revive hooks, Soul token, SoulsPower, epoch gating and character configuration.
   - Use existing generic Env commands and state semantics. If a shared engine gap is confirmed by source, fix it once for all models and add a focused contract test.
   - Leave potion model and pool implementation ownership to the parallel task; make the necessary potion behavior observable through an integration contract without duplicating its model changes.
3. **Differential coverage**
   - Add Oracle cases for all 91 cards at base and upgraded level, all eight relic obtain/effect paths, Osty lifecycle and all Powers/generated-token paths, and all epoch filters.
   - Check choice prefix order and snapshot restoration on each selection-capable path; preserve/save the original Oracle and simulator outputs used for each comparison.
   - Exercise potion IDs/effects only if the parallel implementation is present. Otherwise record that pre-merge dependency precisely and run every other Necrobinder case.
4. **End-to-end acceptance**
   - Establish at least one complete three-act Necrobinder route that compares every path decision, every act's combat/events/rewards/relic obtain, and cross-act state against Sts2Oracle.
   - After the inventory is complete, run fresh random three-act exploration rounds with at least 100 distinct newly sampled seeds per round; persist each seed and unfiltered outcome. Require zero path divergences and zero `Unported`. Legal death counts as a completed run; fixed regression seeds do not count.
   - Run the requested full `scripts/check.sh`, report raw command results, and preserve any failure or unavailable integration as a limitation.
5. **Close out without merging**
   - Update roadmap and README status, add an execution report with commands, raw results, seed corpus, test/oracle limitations, and potion merge dependency.
   - Commit only this feature branch; do not merge `main`. After both branches merge, coordinate a joint full-run replay with the potion task.

## Acceptance criteria

- Card pool is exactly 91 models, base and upgrade behavior covered; hidden/generated Necrobinder token cards and their flags/factory registration are exercised.
- Relic pool contains exactly eight models and honors the Epoch 3/Epoch 6 candidate filters; relic pickup and effects are Oracle-compared.
- Character start matches 66 HP, 99 gold, 3 energy, the ten-card deck and Bound Phylactery. The source `UnlocksAfterRunAs => Regent` metadata is recorded; this Env baseline requires an all-unlocked profile and does not simulate career unlock persistence, so that profile-level side effect is not claimed as an in-run behavior check.
- Epoch 2/5/7 cards and Epoch 3/6 relics filter in source order from actual unlock state.
- Osty summon, max-HP growth, death, revive, pet ownership, damage prevention, turn processing and linked card/relic/power behavior match source and Oracle.
- Selection prefix/snapshot replay restores all relevant combat/run state and RNG; generated candidates and insertion positions follow original source/RNG order.
- At least one full three-act route plus every fresh 100-seed exploration round meet zero path divergence/zero `Unported`; each raw result and seed list is stored.
- `scripts/check.sh` passes, or its exact failure is reported honestly if the integration environment blocks it.
- No Necrobinder potion implementation is duplicated in this branch; the report identifies whether the parallel branch has merged and which potion checks were actually possible.
- No merge into `main` is performed.
