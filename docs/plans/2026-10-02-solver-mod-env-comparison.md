# CombatSolver Mod：原版与 Env 顺序搜索比较

用户目标：在可安装的完整 Solver Mod 中，设置一次搜索预算，从同一实时战斗根先后运行原版和 sts2sim Env 搜索；UI 比较实际耗时、完整/部分结果和文字操作。Env 路线仅展示，自动执行始终使用原版结果。最终交付可放入 mods 的成品。

基线：sts2sim `90eed1b`；CombatSolver 子模块 `d7b46203`（0.47.3）。原版游戏 v0.111.0、单人、当前 Env 支持的全解锁档案。已有用户文件删除不属于本任务。

## 实现

1. 独立搜索消费者原生 C ABI：加载当前 Env 完整快照，调用现有 `CombatSolver::Solve`，返回只读结构化结果和逐动作文字所需的模型身份；支持共享配置、取消、错误隔离和所有权释放。搜索能力不混入通用 Env 公共 API。
2. 主线程捕获实时根：完整拥有型值，不用 seed 重开替代当前局面。复用历史 live mapper 中可核验的字段采集，升级到当前快照格式；根不匹配、未知内容或不支持状态明确报告。后台不得访问实时对象。
3. Mod 协调器：同一冻结根、同一不可变预算（时间、节点、Beam、选择分支、线程）顺序执行；每种搜索各自获得一次相同上限，记录实际工作量和独立计时。节点定义差异在详情解释，不能宣称相同计算量。取消、战斗变化和异常必须回收两端工作。
4. 中英 UI：原版/Env/顺序比较入口，预算、进行阶段、耗时、获胜/死亡/部分路线、战损、最终 HP、药水及逐回合文字操作。结果独立保存；Env 结果类型不含可部署的原版 PlanAction。
5. 保留原版自动执行、自动搜索、续用和取消行为。比较期间不执行任何一路动作；结束后原版路线沿现有资格检查提供给用户。
6. 打包原版 Mod 加必要原生搜索库及许可证，文档写明平台、依赖和安装方法。当前先完成 Linux；用户的平台回复决定是否同时交付 Windows。无外部发布。

## 验收（完成必须逐项有实际证据）

- 原生 ABI：实际搜索、结果重放、源不变、取消、非法/损坏输入、错误后可复用；DLL/共享库从成品目录加载。
- 实时根：普通开局、已出牌的中途回合、不同角色、药水/选择相关状态，原版与 Env 的起点事实/RNG及执行后结果对拍。不能以消费者模板默认值掩盖未捕获字段。
- 顺序比较：两次搜索不重叠，配置数值一致，各自计时；一端失败时 UI 保留另一端真实结果，不伪造比较成功。
- 自动执行隔离：Env 单独搜索与比较都不能将 Env 路线送入部署；原版自动执行实际回归通过。
- UI：预算可编辑并保存，阶段/取消/错误/完成/部分结果可见，长路线可滚动，中英文字齐全；真实 Godot 界面验收。
- 构建与相关合同通过；sts2sim 合入 main 前完整 `scripts/check.sh`；最终从记录的源码构建成品。
- 包含正确 manifest、托管 Mod、目标平台原生库和许可证，不包含游戏 DLL、原始日志或开发源码。

## 状态

2026-10-02：已完成 Linux 交付范围。`sts2solver` 使用私有 ABI v1 调用当前逻辑 v4 Env，未改变普通 Env ABI；Mod 在主线程捕获实时根，在后台按同一不可变预算先跑原版、再跑 Env，并把 Env 结果限制为文字展示。真实 Godot 无头 UI 场景 `ENV-COMPARISON` 通过：原版 1484.3 ms、Env 419.3 ms，同根 HP 62/62；预算持久化、英中英切换、取消、实时根不变和 Env 不部署均通过。Ironclad 原版自动执行 `SMOKE-001` 也通过。五角色 live bridge 覆盖了药水、不同角色、开局和中途回合；Silent 在 500 节点开局返回 partial，属于真实预算边界，未被伪造成胜利。完整证据见 `docs/reports/2026-10-02-solver-mod-env-comparison.md`。
