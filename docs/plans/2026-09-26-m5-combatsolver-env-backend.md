## 目标

在 CombatSolver 原有 Beam Search、评价、剪枝和预算政策上接入 `sts2sim` 状态转移，制成可由正版游戏加载的新 Mod。用户可选原生预测或 Env 预测，也可同时运行并比较。两种模式必须从已核对的同一个 live 根出发；任何未移植、状态不全或后继分歧都明确停止使用 Env，不把结果作为可部署建议。开放可复制、可逐步预测、可读取后继和失败原因的 Env 接口，供未来预测使用。

## 用户确认的最终交付标准（2026-09-26）

- **安装包**：交付可直接放入游戏 `mods` 的 `CombatSolverEnv/` 文件夹，包含清单、DLL、当前平台的 Env 原生库和许可证；明确列出实际需要的依赖及与原版 Mod 的启用关系。玩家运行时不需要源码、编译工具或手工配置环境变量。
- **游戏内设置**：UI 提供 Native 与 Env 两种搜索后端，设置持久保存；额外提供性能对比开关。切换发生在安全的决策边界，取消旧后端的搜索并使旧结果失效，避免两个后端同时部署动作。
- **直观性能对比**：显示实际使用的后端、搜索耗时、展开节点数、节点吞吐、状态克隆及转移耗时、结果一致性。对比输入来自同一个冻结根并使用同一算法与预算；分别展示根导入和搜索成本。若并行运行，标明资源竞争；可比较的速度倍数必须来自相同运行条件。
- **完整替代**：在声明支持的内容范围内，Env 模式的所有搜索分支、状态克隆、动作预测和跨回合推进由 C++ Env 完成，保留 CombatSolver 原来的候选、评价、剪枝和预算规则。游戏只负责冻结 live 根与执行最终动作；不能在 Env 模式暗中调用原生预测补算，也不能只验证 native 最终路线或只接管首回合。
- **失败透明**：未移植内容、根导入缺失或预测分歧时，UI 明确显示 Env 未使用及具体原因。回退 Native 要显示实际后端；回退场景不计为 Env 完整替代的验收成功。
- **成品验证**：安装包通过隔离正版游戏的加载、UI 设置与持久化、后端切换、连续回合、选择与药水、部署、未移植拒绝及性能对比验证。交付报告写明实际验证过的角色、内容与平台范围。

当前开发包尚不满足以上标准；完成预测接口或加载测试不等于成品完成。

## 已核实的前置状态

- 正式遭遇模型 90/90；`scripts/check.sh` 的固定种子门禁在前一分支报告中通过，不等于全部内容已移植。
- 现有 `Sts2EnvCompare` 是独立开发版 Mod：CombatSolver 用 Beam Search，Env 用参考 ISMCTS；只按种子重建首回合并核对结构子集。它不满足同算法、任意 live 根或可切换后端。
- CombatSolver 的 `CombatRootSnapshot` 在主线程捕获完整预测根；`CombatBeamSolver` 的展开、评价、保路与终局排序直接使用其 C# `CombatPredictionSimulator` 状态。替换模拟器需要明确的状态与动作适配，不能仅替换一次 `Solve` 调用。

## 工作项

1. **预测接口与失败边界**（`env/c_api.*`、`python/sts2sim_env.py`、`python/test_env.py`）：提供纯分支转移和当前状态检查；将 `Unported` 与其他错误分开，失败不改动源状态。此接口只建立后续后端所需的预测能力，不把参考 ISMCTS 视作同算法实现。
2. **完整根合同**（`engine/sim/state.h`、`env/`、新桥接协议及 Mod）：从 CombatSolver 已冻结的 live 根导入所有影响下一步的字段，包括卡实例与费用/附魔、全部牌堆、遗物/药水内部数据、能力、怪物状态机与意图、RNG 和战斗历史。导入后逐字段及逐动作与 oracle/原生预测对拍；未知字段拒绝 Env 后端。
3. **同算法接入**（CombatSolver 派生代码、新 Mod）：保留现有 Beam 候选生成、评价、保路、终局和预算定义，用 Env 的分支状态与转移替换对应预测路径。禁止把 ISMCTS rollout 与 Beam expanded 当作等价工作量。
4. **双模式与保护**（新 Mod 的设置、运行时、日志、界面）：游戏内提供 Native、Env 两种后端与独立性能对比开关，持久保存设置；现有 `env/native/both` 环境变量只作为开发测试入口。对比在同一根、同一搜索政策下采集原始耗时和工作量；根不同、未移植、预测差异或 live 已推进时不部署 Env 结果。Env 专用模式遇到这些情况也明确回退原生或停止，并向玩家说明实际后端。
5. **游戏内验证**：构建并装入隔离正版游戏；覆盖首回合、后续回合、复杂牌组、选择、未移植内容和动作部署。提供可复现日志及同算法同预算的比较报告。

## 验收

- C++/Python 预测接口：成功时后继与独立 clone+step 相同，源状态不变；非法动作或未移植时无后继且原因明确。
- 完整 live 根及每一步的预测与原生状态逐字段一致；不足时记录具体缺口并禁用 Env 模式。
- 两种后端执行同一 Beam 搜索政策和预算；在游戏内可选、可双运行，输出各自原始时长、工作量、首动作及根/后继核对结果。
- Env 搜索遇到未移植内容绝不继续产生或部署建议；`scripts/check.sh` 全门禁和针对 Mod 的隔离游戏测试通过。

## 当前进度

第 1 项已完成：C ABI/Python 提供纯分支预测、状态检查、根覆盖拒绝和明确的 `Unported` 状态。另已增加一个确定性 Beam 形状的 Env 后端、节点预算/宽度参数和 Mod 的 `env`/`native`/`both` 三模式；它复用了 Beam 的展开/保留结构，尚未复用 CombatSolver 的完整候选、评价、终局和部署策略。

Mod 还提供了持久 Env session，逐次 `Predict` 返回独立后继并保证源状态不变；每次开发版搜索会验证一次该边界。参考 Beam 现在保留 `plan`，`env` 模式可在当前回合逐步部署 `PlayCard`/`EndTurn`，每一步重新核对 live root。

在 `both` 模式，Mod 还会读取 CombatSolver 的实际 `BestNode.Actions`，将当前回合 native 路线按卡牌 occurrence、目标和药水槽位逐步送入 Env session 做只读转移验证；这建立了原生策略到 Env 预测边界的可观测检查，但尚未把 Env 替换成 CombatSolver 的搜索状态后端。

已建立 `tools/CombatSolverEnv` 独立派生构建：直接链接固定子模块的完整搜索源码，仅生成修改 Mod ID 的原生初始化器；同时编入 Env 桥接，游戏中两个初始化器来自同一派生程序集。隔离场景验证了原生搜索与 Env 路线重放检查，避免未来接入时另写搜索政策。下一项仍是完整根合同及原生 `SimulationSnapshot`/预测状态与 Env 的适配，不能以源码链接或路线重放代替后端替换。

第 2 至 5 项仍是本计划的完成条件，不能以 Beam 形状参考后端代替完整同算法接入。当前 Mod 在 `env` 模式可以暂停原生搜索、按计划部署当前回合的合法卡牌/结束回合动作，然后恢复原生搜索；跨回合、选择和完整路线仍由原生接管。后续必须先完成完整 live 根合同和逐动作对拍，再扩大 Env 部署范围。

已将结构后继核对接入原生 Replay/ReplayAction 与回合准备后根，独立 Env session 随快照释放；并行源访问加锁。自然首回合根的短搜核对已覆盖进入第二回合的 EndTurn。默认测试器会额外注入 Strike，新增核对明确拒绝这类种子重建根不一致的场景。公开 `CombatSolverEnv.Api` 提供 owned session 与 `Ready/Unported/Error`；仍明确限定为种子战斗入口。健壮性检查还修复了原始 POD padding 导致的哈希不稳定，改为完整字段编码与生成 schema 门禁。这些进展支持第 2/3 项的核验，不代表这两项已完成。

完整 Env 逻辑快照导出已加入 C ABI 与公开 `CaptureSnapshot`，保留 RNG、内部字段、槽位/空闲链、选择重放根及精确数值位。生成遍历提供命名字段与 schema 摘要，供 live mapper 审计；尚无完整 live 输入实现。分支检查进一步覆盖九条战斗 RNG 的完整状态，自然根 100 节点/343 累计 Env 转移核对通过，包含进入第二回合；所有核对时间仍包含在 native 耗时内。这项证据不能扩大到怪物实例 RNG/FSM 或完整后端替换。

版本 2 增加完整 combat/choice 文档导入与独立 owned restore，检查 schema/runtime、字段/数值、容器与引用、状态机归属及 choice 重放。C ABI、C#、Python 均能恢复明确输入的状态，且未移植仍单独拒绝。已验证恢复后的后续回合与选择、存储未来分配顺序及失败不改变源；游戏内种子根也经过完整传输边界。当前仍须实现 native/live 所有游戏字段到该文档的映射，不能用恢复已有 Env 快照代替这项条件。

真实卡牌组件开始接入：在主线程稳定性检查内冻结实际实例、五个牌堆、deck、费用修改/临时费用、本地关键词、基础变量与实例引用；未知子类数据和附件明确拒绝。使用正版卡牌对象的独立工具验证组件恢复到 C++ 后能驱动动作，且 live 修改不影响冻结值。其余根字段仍待映射，生产分支核对继续标记种子来源；该组件不构成完整 live 根或 Env 后端完成证据。
