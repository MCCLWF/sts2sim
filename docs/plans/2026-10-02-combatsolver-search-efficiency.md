# CombatSolver 搜索效率续优化

用户目标更新为：继续优化，并添加多线程支持。基线为 main 76abc78；此前用户接受搜索组织不同、效果接近，
要求保留通用 Env/规则，暂不开发 nosl/训练。先前全分支功能已合入 main，原主树
CLAUDE.md 删除保留；本轮在已有干净附属工作树开性能分支，结束后合回 main 并清理。

## 问题与方向

21 场同预算开局样本：原生展开 125892、上游 39354；原生 97 个 Pass 从根重搜。
上一轮缓存降低执行成本但没有减少展开。当前每轮转置表独立，父节点没有独立的展开准入表，
且逐回合 Beam 的保路/组合比较简单。不能将跨不同宽度/集中目标的旧展开记录直接用于
全局跳过，否则会丢失本轮应保留的候选。

1. 冻结主线二进制与输入；记录每个 Pass 的宽度、目标、工作量及候选质量。
2. 先检验完整状态/成本标签的父节点展开准入，保持六维政策与真实规则执行。
3. 根据实测调整重复搜索/候选保留或复用方式，降低真正执行的工作量；不能只改计数、
   缩小预算或为了提速牺牲已验证的获胜能力。效果发生变化时记录全部单场差异。
4. 保留返回路线从根实际重放、完整 hash 校验、根与兄弟状态独立、Choice 前缀、
   无药基线与 Smart/Disabled/Required 反事实、共享请求时间/节点预算。
5. 必要时拓展到带实际牌组/遗物/药水/嵌套选择的非起始牌组场景；不将起始牌组 Boss
   部分路线探针当作中后期胜率验收。新增集中目标组合的并行调度，任务独立状态，
   节点配额不重叠、时间共用请求起点，保留药水反事实和确定的目标合并顺序。
6. ThreadCount 默认1。普通基线先行，集中成员并行；如有效目标不足，不宣称能用满
   指定核数。大状态缓存不按线程复制，小值缓存按当前任务数分配；测 GNU time CPU/RSS。
