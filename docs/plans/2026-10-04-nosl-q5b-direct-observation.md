# NoSL Q5-b：实机直接从游戏对象编码观察——去掉影子和种子

- 日期：2026-10-04。分支：`feat/nosl-q4d-reward-fix`（与 Q5-a 同一条线）。
- 上级需求：[Silent A10 整局 NoSL 计划](2026-10-03-silent-a10-nosl.md) I01（actor 输入由公开信息构成）、I02（训练编码与实机编码逐状态对照）、
  §10（部署无隐藏未来输入）、§13 第一、六条。
- 前置：[Q5-a 报告](../reports/2026-10-04-nosl-q5a-live-pilot.md)。Q5-a 的执行器靠同种子的影子模拟器取得观察，进程持有种子，这一条不满足成品的信息边界。
- 本计划的第一步（对照）在登记时已经做了一部分，结果写在“已经知道的”一节；第二步（去掉影子）还没有做。

## 问题

**问题 1（编码一致）**：Mod 只读游戏自己的对象（界面上显示的、玩家能查看的），生成 `nosl.obs` v1 的三张表和合法动作表，
能不能在每个决策点都和模拟器 `nosl::Observe` 的结果一致？

**问题 2（不带影子运行）**：去掉影子之后，Mod 自己判断“现在是哪种决策”，用自己编码的表做决策，能不能照样打完整局？

## 做法

1. `tools/NoslPilot/Observer.cs`：`nosl/observation.cpp` 和 `Env::LegalActions` 的 C# 对应物，输入是游戏对象：
   玩家、遗物、药水、手牌与三个牌堆（按内容计数，不看顺序）、敌人与意图、地图、奖励、事件选项、休息点、商店、宝箱、选牌请求。
   内容编号用原生库按条目名查（`nosl_id`），文本键用同一个 FNV-1a 分桶。
2. 原生侧把决策拆出来：`nosl::Actor`（过滤器 + 前向 + 抽样）只吃表，不需要 Env；`nosl_actor_decide` 是它的 C 入口。
   影子（`nosl::Pilot`）和游戏侧编码走同一个 Actor，表相同则动作相同。
3. 对照模式（影子仍然驱动）：每个决策点，Mod 的表与 `nosl_pilot_observe` 给出的影子的表比较——全局向量逐项、token 按多重集、
   每个动作行连同它指向的 token 内容。不一致写日志，不停机；局末汇总各类决策的比较数和一致数。
4. 直接模式：Mod 按界面状态自己判断决策种类（战斗出牌阶段、奖励界面、卡牌奖励界面、地图、事件、休息点、商店、宝箱、选择器回调），
   编码、调用 `nosl_actor_decide`、执行。进程里没有 Env，也没有种子。影子可以作为可选的旁路对照同时开着。

## 判据（除“已经知道的”以外，结果出来前固定）

1. **编码一致**：对照模式下，至少 30 个 dev 种子、两个不同策略的整局，报告每类决策的比较数与一致数。
   判“一致”要求全部比较相同；每一种不一致都要定位到是哪一侧的问题（Mod 的编码、模拟器的编码、还是模拟器的规则移植），并写明处理。
2. **直接模式整局**：至少 20 个 dev 种子从新开局打到游戏结束，进程里没有影子、没有种子。全部尝试都报告。
3. **与影子方案一致**：同一种子、同一策略种子，直接模式的动作序列与干跑逐步相同。地图节点 token 的顺序两边已统一；
   若仍有浮点舍入造成的极少数分叉，报告局数和分叉点，不算失败，但要说明。
4. **审计**：直接模式的进程不加载 Env 的重置/推进入口；`nosl_actor_decide` 的输入只有 Mod 编码的表。列出 Mod 读取的每一类游戏对象，
   说明它们为什么是公开的。
5. 阶段覆盖照 Q5-a 的口径列出，没走到的写“未验证”。

## 已经知道的（登记时）

对照模式第一次运行（`NOSLDEV0163`）86 次比较里 80 次相同；14 个种子 2,537 次比较里 2,503 次相同。所有不一致都在模拟器一侧，已修：

| 不一致 | 原因 | 处理 |
|---|---|---|
| 地图观察多出 6 个节点 | 模拟器的 `map.points` 留着生成器创建后又剪掉的点，游戏地图上没有 | `nosl::Observe` 只列网格里的点，按网格顺序 |
| Silver Crucible 的状态晚一个房间才变灰 | 移植只在进房间时检查用尽，正版在使用次数的 setter 里就检查 | 照正版改 |
| Kusarigama 战斗结束后状态应为 Active 却是 Normal | 正版 `AfterCombatEnd` 里 `IsActivating = false` 的 setter 会重算状态 | 照正版改 |
| 附魔选牌的来源名不同 | 五处移植调用了 `FromDeckGeneric`，正版是 `FromDeckForEnchantment` | 照正版改 |

这些都是只管显示的状态或标签，不影响规则，所以 oracle 对拍一直是绿的；但它们会进观察。修完后重跑出问题的种子，比较全部相同。
完整的 30 个种子对照（判据 1）还没有跑。

地图那一处改动了训练用的观察（少了看不见的节点），对已有模型是一次很小的输入分布变化；Q4-d 的运行仍用旧的采样库，之后的实验用新的。

## 预算

实机测试每局约 35 s（Instant）或 140 s（Fast），一次一个实例。
