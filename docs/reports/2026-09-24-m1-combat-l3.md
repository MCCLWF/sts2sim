# 报告：M1-d～f、M1-h 战斗引擎与 L3 零分歧

日期：2026-09-24　分支：`feat/combat-engine`

## 结论

铁甲战士起始牌组打第一幕首层的全部 8 个弱遭遇，oracle 用带种子的随机策略出牌，C++ 模拟器按同样的动作重放。A0 和 A10 各 1000 场，**每个决策点的完整战斗状态与游戏 0 分歧**，战斗结束时的血量和各 RNG 流计数器也一致。

## 验收命令与结果

```text
SEEDS=BIG0000..BIG0499（500 个）
Sts2Oracle combat --seeds $SEEDS --characters IRONCLAD --policy-seeds 3,4 --ascension 0  > big0.jsonl
tests/l3/l3_combat.py --trace big0.jsonl --ascension 0
  L3 combat: 1000/1000 combats identical, 18771/18771 states matched
Sts2Oracle combat ... --ascension 10 > big10.jsonl
tests/l3/l3_combat.py --trace big10.jsonl --ascension 10
  L3 combat: 1000/1000 combats identical, 19698/19698 states matched
```

遭遇分布（60 种子 × 2 策略的 A0 样本）：
- Nibbits 24、Seapunk 16、SludgeSpinner 16、ShrinkerBeetle 16、FuzzyWurmCrawler 14、Toadpoles 14、CorpseSlugs 10；
- Slimes 10（四种大小史莱姆组合都出现了）。

强制遭遇（每个 8 种子）：Toadpoles、Slimes、CorpseSlugs、Nibbits 全部一致。未移植的遭遇（例如 FlyconidNormal）报 `Encounters.FlyconidNormal.GenerateMonsters is not ported`，不会静默继续。

A10 样本确认进阶生效：牌组里有进阶之灾，药水栏 2 格，怪物数值切到 ToughEnemies / DeadlyEnemies。

## 已知限制

- **选择前缀机制（M1-g）还没接上**：`Sim::Choose` 和 `NeedChoice` 已经有了，但还没有需要选择的已移植内容，也没有环境层的快照重放。oracle 侧也还没有选择卡牌的策略（O-012）。
- **只覆盖首层弱遭遇和起始牌组**：其他遭遇、卡牌、遗物、药水在调用到时抛 `Unported`。
- **战斗离开房间（`CombatRoom.Exit`）、奖励、非战斗房间还没移植**：这些是 M1-i 的内容。
- **对象池回收**：C# 靠 GC 回收战斗对象，模拟器的池槽位还没有在战斗结束时回收。整局运行（M1-i/j）前必须补上。
- **只比对了状态行里的字段**：RNG 流计数器和每个怪物的 Rng 计数器已经在状态里，所以多抽或少抽一次随机数都会被发现；但同样次数、不同参数的抽取只能靠后续状态分歧间接发现。C++ 侧的逐次抽取账本还没做，目前没有分歧，暂时不需要。
