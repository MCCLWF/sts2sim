# Silent A10 整局 NoSL：研究结论与计划交付

## 范围与结论

用户最终目标是 **Silent A10 的整局高水平操作，部署时无搜索、无未来模拟、无试动作回滚，只使用公开信息与历史**。本轮只研究和写需求计划，没有训练模型、生成教师数据或修改游戏规则。

交付：[需求与探索计划](../plans/2026-10-03-silent-a10-nosl.md)。确定目标与判据，保留算法、网络、后端及推进顺序的选择空间。当前较值得试验的假设是少量战斗示范初始化后接在线 RL；它不是已证明的最佳路线。

继续投资 Env 的理由可以从“与现有启发式搜索对齐”转向“为学习提供保真、大量、可并行的完整跑局交互”。是否真的形成优势，仍需测完整学习流水线和新策略访问路径，而不是引用旧微基准承诺训练效果。

### A0 与 A10 的关系

本地 `Entities/Ascension/AscensionLevel.cs` 定义 A10 为 DoubleBoss，低等级修正逐级累计；[`engine/run_setup.cpp`](../../engine/run_setup.cpp) 实现药水槽减少、AscendersBane 与最终幕双 Boss 配置。A10 不只是同一战斗加少量 HP：资源、构筑及长局分布也变化。

因此 **A0 模型权重可以复用，通常应继续训练/微调或混合难度训练；不必从零重训，也不能承诺直接迁移后的 A10 水平**。首次学习闭环可用较低难度，但目标角色始终是 Silent，A10 应早期进入留出诊断，不以 Ironclad A0 完成为前置要求。

## 性能证据应该怎样解读

### 旧战斗搜索比较

[同机比较报告](2026-10-02-sts2-ai-latest-comparison.md)的三轮 21 场起始牌组结果如下，均使用报告中冻结版本和对应预算口径：

| 配置 | 合计搜索秒中位数 | 合计战损 | 限制 |
|---|---:|---:|---|
| sts2sim 1 线程 | 46.29 | 349 | 原生简化移植，非完整上游评分与调度 |
| sts2sim 2 线程 | 42.11 | 349 | 成员并行约快 9%，CPU/RSS 增加 |
| 本地 sts2-ai Beam | 44.42 | 456 | 现有私有仓库版本 <私有提交>，不能称最新私有版本 |
| 原版 CombatSolver | 35.62 | 350 | d7b4620，单线程原版搜索 |

原生与原版 14 场相同、4 场更好、3 场更差，最差单场多损 15 HP。349/350 的合计接近不能说明逐场策略等价，更不能说明复杂实机战斗或 A10 整局等价。用户后续实机反馈“大多耗时更长、效果更差”，目前是有效问题线索，尚无记录好的比例与复杂根统计。

原生搜索做更多工作但收效不明显，主要候选原因是候选筛选、启发式保留、重搜组织与停止规则，而不是 C++ 语言天然更慢。为 NoSL 成品补齐这些搜索差异只有在改善教师/数据成本时才值得，不能继续当主目标。

### Env、通信与训练吞吐

较新的 180 个共同根测量中，PlayCard 约 36.77 µs（C++）/36.11 µs（C#），EndTurn 约 124.55/124.84 µs；独立 Env 八线程吞吐约为单线程 5.65 倍。这是特定操作/状态的历史证据，说明独立采样有潜力，不是完整跑局训练 benchmark。[同机 Env 数据](2026-10-02-sts2-ai-latest-comparison.md)

此前约 0.5 ms ctypes“完整回合”实际上包含 **Clone + EndTurn + Observe + LegalActions**。不能把它全部算作 Python 通信，也不能直接推导不克隆的训练 step 成本。Python decoder、观察内容和重复长度查询都需在真实学习路径单独计量。[接口基准](2026-10-01-env-performance-compare.md)、[原始工具](../../tools/bench/compare/interfaces.py)

sts2-ai 1.34 calls/s 的旧产品服务测量包含内部战斗搜索。该数值不是裸 C# 模拟速度，也不是 gRPC 必然造成的吞吐。NoSL 原版引擎后端应重新测量；Env 的优势也应以推进、编码、模型推理、reset、数据传输和训练更新合计衡量。

本机研究时的只读检测：RTX 5060 Laptop GPU、8151 MiB 显存、驱动 595.84；系统 14 GiB 内存、约 8.6 GiB available，swap 使用 3.5/4 GiB，系统盘约 16 GiB 可用。检测不等于已验证训练软件栈、模型大小或训练耗时；先小试再扩大教师并发与数据规模。

现有 [OfflineSearchHarness](../../external/CombatSolver/docs/OFFLINE_SEARCH_HARNESS.md) 不启动 Godot，使用新跑局/生成场景建根，再调用生产搜索输出路线与指标；该宿主不替代原生无人正确性测试。任意学生中途根的恢复、动作标签与持续自动采样，仍要逐项确认或适配，不能把“能跑一次搜索”当作完整教师数据流水线。

## 算法研究：能支持什么，不能保证什么

以下依据原论文或作者发表页面。它们没有提供本项目 Silent A10 的学习结果；所有迁移到 STS2 的效果判断都是待验证假设。

### 模仿初始化与在线强化学习

PPO 用环境交互采样，再多轮优化策略目标；它不需要教师作为能力上限。在不同合法种子的真实随机轨迹中，学生有机会学会特权教师没有示范的风险折中。但它不能自动消除观察缺失、模拟器错误、长回报或分布覆盖不足。[PPO 原论文](https://arxiv.org/abs/1707.06347)

Policy Distillation 证明了从已有策略向学生转移知识的可行性，但不证明全知搜索路线能直接变成高水平公开信息策略。若我们只有路线单动作标签，更准确的首个方法名是行为克隆；软动作分布/价值标签另需采集。[Policy Distillation](https://arxiv.org/abs/1511.06295)

采用示范后继续 RL 是合理候选。特权动作标签作为初始化的风险，低于把它们当最终公平答案的风险；仍需比较示范的闭环净收益与计算投入。没有证据要求先建 expensive fair ensemble，也没有证据证明一次低预算搜索对所有复杂牌组都足够。

2026 年的 actor-critic pretraining 研究在模拟机器人任务中，用 BC 初始化 actor、用该 actor 轨迹回报初始化 critic，报告了样本效率改善。它支持将 critic 预热纳入小试；不支持断言“未预热一定崩溃”或本项目必然获得同样增益。[Actor-Critic Pretraining for PPO](https://arxiv.org/abs/2602.23804)

DAgger 用学生实际访问状态再询问专家，针对分布偏移；若专家标签依赖隐藏未来，它并不会因此成为公开观察的唯一正确标签。原教师能否恢复学生根及标注成本也需实测。[DAgger](https://arxiv.org/abs/1011.0686)

### PPO、AlphaZero 类方法与 NoSL

| 方向 | 对当前目标的意义 | 主要代价/限制 |
|---|---|---|
| BC → PPO / 其他在线 RL | 可减少初期无效操作，在线回报允许超越教师 | 两次阶段切换、示范分布偏移、critic 与训练稳定性 |
| 直接 PPO / 在线 RL | 无教师需求，直接面向真实任务 | 初期探索昂贵；战略稀疏、长回报和合法动作处理 |
| Expert Iteration | 搜索产生目标，学生泛化，再指导后续离线专家 | 搜索成本与信息边界；学生无搜索表现须单独测 |
| 原版 AlphaZero | 策略/价值引导 MCTS 的典型参照 | 原方法部署也搜索；STS2 随机、部分可观测、多阶段任务需要改造 |
| 搜索训练后蒸馏成纯策略 | 可满足部署 NoSL 的另一个候选 | 不能把去搜索后的强度默认等同完整搜索系统 |

Expert Iteration 的原始实验将树搜索与学习互相改进；AlphaZero 在确定性、完全信息棋类中结合策略/价值网络和训练/对弈搜索。因此这里可借鉴离线专家迭代，但不能直接指定原版 AlphaZero 作为无搜索上线方案。[Expert Iteration](https://arxiv.org/abs/1705.08439)、[AlphaZero](https://arxiv.org/pdf/1712.01815)

### 信息、记忆、合法动作与课程

训练期使用全状态 critic、部署期使用部分观察 actor，有原始 asymmetric actor-critic 研究支持。但在本项目中，actor 的历史与 critic 输入合同仍须明确，不能让共享特权特征进入部署。[Asymmetric Actor Critic](https://arxiv.org/abs/1710.06542)

合法动作 mask 是策略梯度可采用的手段；游戏中的实例绑定、可变候选、Choice 顺序及采样/更新一致性仍是额外工程要求，不能由一个 mask 接口替代。[Invalid Action Masking](https://arxiv.org/abs/2006.14171)

课程学习有多种任务排序与难度设计，并没有一条规定“先完整练成 A0，再训练 A10”的通用路线。我们应比较直接 A10、低难度迁移与混合课程，选择成本/质量更合适的方式。[Curriculum Learning for RL: A Survey](https://arxiv.org/abs/2003.04960)

### 奖励、截断与可信评价

任意楼层、HP 或构筑分数奖励可能改变最优行为。经典潜势塑形讨论了保留原目标的条件；采用它必须处理折扣、终点与固定潜势，不能用不断变化的学习分数完全替代真正胜负。[Policy Invariance under Reward Transformations](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)

时间界限研究区分任务真正终点与训练采样截断的 bootstrap 语义。Unported 或执行故障缺少可信后继，不是该论文讨论的普通采样截断；应隔离并报告，不能直接当死亡或无条件 bootstrap。[Time Limits in RL](https://proceedings.mlr.press/v80/pardo18a.html)

强化学习评价容易受少量训练随机种子和聚合方式影响。最终报告应给出独立跑局样本、训练重复、区间估计及成本；预算有限时如实报告不确定性，不能用大量同局步骤放大统计样本数。[Deep RL at the Edge of the Statistical Precipice](https://arxiv.org/abs/2108.13264)

## 对此前建议的采纳与修正

1. **采纳**：模仿后在线学习值得小试；完整跑局才是目标；强策略访问路径需要持续原版对拍；观察和动作必须完整；后期与全局执行仍缺证据。
2. **保留开放**：“两策略共享编码器一定更好”“先原生 batch 再训练”“全部 PPO 放 C++ Env”都不是现有证据的必然结论。冻结战斗策略同时更新共享编码会改变它，需明确冻结范围。
3. **教师参照修正**：全知但有启发式误差的求解器是特权参照，不是数学上界。多世界价值平均若每个世界内继续全知搜索，也可能高估公开信息后续策略，不自动构成公平教师。
4. **奖励修正**：战后 run value 可以辅助，但实际胜负目标仍保留；阶段/宏动作折扣需符合时间跨度。
5. **错误处理修正**：Unported 与分歧不是普通学习 truncation。隔离故障并记录全部尝试的完成率，避免只算成功样本。
6. **难度修正**：以 Silent A10 为首个成品，A0 和 Ironclad 仅可作辅助；不要求从 A0 重新从零训练。
7. **后端修正**：原版 DLL/Godot 可作教师与采样候选。旧架构“不直接当环境”的搜索吞吐动机不构成 NoSL 学习后端禁令；实际吞吐、恢复与成本再决定分工。
