## 1. 交付内容

| 部分 | 路径 | 说明 |
|---|---|---|
| 与 .NET 逐位一致的基础组件 | `core/` | Xoshiro256** + SplitMix64（`MegaRandom`、`Rng` 及计数器）；XxHash64 种子派生；`Dec`（System.Decimal，含 `DecCalc` 的舍入、刻度和零符号规则）；`dotnet_sort`（.NET introsort） |
| golden 生成器 | `tools/rng_golden` | 直接编译游戏的 `MegaRandom.cs`、`Rng.cs`、`ListExtensions.cs`、`ModelId.cs`，一行不改，并使用游戏自带的 `System.IO.Hashing.dll` |
| 内容导出 | `tools/Sts2Exporter` → `data/content.json` | 在普通 .NET 进程里运行 `sts2.dll`，导出全部模型：数值、覆写了哪些 Hook、升级差值、进阶差值、卡池 |
| 代码生成 | `tools/gen/gen_content.py` → `content/generated/` | id、枚举、成员表、静态数据表，以及 `modeldb::` 访问器 |
| 无头 oracle | `tools/Sts2Headless`、`tools/Sts2Oracle` | 不需要 Godot：原生函数表用桩函数填满，引擎单例预先播种，纯表现层代码用 Harmony 补丁跳过，存档放内存。`newrun` 命令输出存档 JSON 和各幕地图 |
| 开局与地图 | `engine/run_setup.*`、`engine/map.*`、`engine/save_json.*` | 新局初始化顺序、遗物袋、先古、各幕房间预生成、DoubleBoss；地图生成、剪枝、修复、居中、分散、拉直 |
| 对拍 | `tests/l2/compare_newrun.py` | oracle 与 `sts2sim_cli` 使用相同的种子、角色和进阶，逐字段比对 |

## 3. L2 不比对的字段

这些字段不属于游戏逻辑，比对时忽略（见 `tests/l2/compare_newrun.py` 的 `IGNORED`）：
- 墙钟和平台字段：`save_time`、`start_time`、`run_time`、`platform_type` 等。
- 存档档案数据：玩家的 `discovered_*` 和 `unlock_state`。模拟器按全解锁存档运行，见偏离 D-001。
- 当前幕的 `saved_map`：oracle 不会进入地图，这个字段只是占位。地图单独在 `/maps` 下比对。

## 4. 已知限制

- 内容只导出了数值。卡牌、遗物、能力、怪物的效果逻辑一行都还没移植，这是 M1-d 到 M1-h 的工作。
- L2 只覆盖开局这一刻。进入地图之后的任何状态都还没有对拍。
- oracle 默认按全解锁档案运行。依赖真实档案进度的分支（比如首次游玩的引导）没有覆盖，也不打算覆盖。
